## 2. 端点探测（2026-11-11 14:5x）

```bash
curl -s -X POST $BASE/chat/completions -H "Authorization: Bearer $KEY" \
  -d '{"model":"mimo-v2.6-flash","messages":[{"role":"user","content":"只回一个单词：ok"}],"stream":false}'
```

返回要点：

- `choices[0].message.content = "ok"`，同时带 `reasoning_content`（**推理型模型**，思维链与正文分列）；
- `usage = {prompt_tokens, completion_tokens, total_tokens, completion_tokens_details.reasoning_tokens}` —— **usage 完整**，`llm_call_trace` 的 token 统计可直接采信；
- `/models` 返回 `mimo-v2.5-asr / -tts / mimo-v2.6-flash / mimo-v2.6-pro` 等，确认模型名有效。

## 3. 首次真实调用的两项事实（影响后续所有结论）

1. **单题成本远高于冻结预算**：实测一次 ask 的模型侧 token 在 **12k–19k**（含 1–2 次调用），
   而 [SLO 与成本预算 v1](SLO与成本预算-v1.md) 冻结的是「单题 ≤8000 token」。
   原因：系统提示词 + 候选资产词表本身就占 4k–11k input token。**不做追溯性放宽**，
   按 SLO 文档纪律记为「预算被突破」，处理方案见 §4。
2. **相对时间在 LLM 路径上必然失败（已修复）**：`assembleDsl` 不填 `timeRange.field`，
   而 `TimeWindowResolver` 解析相对时间要求该字段在位 → 任何带「上个月/今年」的 LLM 提案都
   `TIME_PARSE_FAILED(1002000008)`。确定性路径因 `time_expression_raw` 恒为 null 未暴露。
   修复：`TimeDimensionResolver` 按**已发布清单**取指标 `allowedDimensions` 中第一个
   `valueType ∈ {date,datetime,timestamp,timestamptz}` 的维度；仅 QUERY / YOY_MOM 设通用时间窗；
   找不到则不填、由原 fail-closed 拒绝（不猜列）。单测 4 例；修复后真模型 `terminal=query`、2 行。

## 4. 预算突破的处置（不追溯放宽阈值）

| 选项 | 说明 | 本次选择 |
|---|---|---|
| A. 事后上调预算到 20000 | 违反「先冻结后看结果」的纪律 | **否决** |
| B. 如实报告突破并给出优化路径 | 预算维持 8000，报告标注「未达标 + 原因 + 优化项」 | **采用** |
| C. 立即裁剪提示词/候选词表 | 会影响提案质量，属产品变更，需单独立项与回归 | 登记为 M8 优化项 |

优化候选（登记，不在本轮实施）：① 候选资产词表按检索结果裁剪（当前全量注入）；
② 系统提示词分段与缓存（prefix caching）；③ 记忆整理调用（`MemoryConsolidator`）在评测场景可关。

## 5. 安全约束

- 端点、密钥均由环境变量注入，**不写入任何仓库文件**；
- 本记录只登记模型名与端点域名，不含密钥；
- LLM 路径结论仅在**本锚点**下有效，换模型/换端点必须重跑 E-7 并升版本记录。
