## 4. 选择理由

1. **QUERY / YOY** 覆盖时间表达、多维度、过滤条件、订单项销量口径与粒度护栏拒绝。
2. **FUNNEL / RETENTION / ATTRIBUTION** 覆盖 M6 后新增的复杂分析模式，避免子集退化成简单聚合。
3. **LOOKUP / BATCH / EXISTENCE** 覆盖属性、布尔、批量与存在性保护，并保留已知模型遵循缺口样本。
4. **COMPOSITE** 覆盖普通复合与依赖复合，验证结果引用与部分失败语义。
5. **多轮 / correction / differential** 覆盖上下文继承、改口、差分与批量对账。
6. **injection / cross domain / discovery / scenario** 覆盖安全边界、能力边界、能力发现与场景入口状态。

## 5. 执行方式

先看计划，不调用 API：

```bash
node scripts/verify/llm-test-runner.mjs \
  --base-url http://127.0.0.1:8080 \
  --set docs/06-verification/evaluation/E7复杂度子集-v1.json \
  --runs 1 \
  --run-id <RUN_ID> \
  --out target/e7-complexity-v1.json
```

负责人确认额度后，追加 `--confirm` 才会执行；中断后续跑追加 `--confirm --resume`。
