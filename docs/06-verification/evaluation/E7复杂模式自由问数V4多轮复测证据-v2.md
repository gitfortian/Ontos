## 4. 两项服务端修复

1. **F-1 输出契约授权词表**：`SessionCandidateContextProvider` 新增 `prime(outcome, question, SessionProjection)`；`candidateVocabulary()` / `candidateVocabulary(question)` 把投影 ID 经「当前清单可解析 + 当前策略快照授权」双重过滤后并入词表。`OntosAgentFactory.questionAware` 契约与提示词候选集同步生效。
2. **F-2 来源完整性对账**：`SessionProjection.assetIds()` 提供语义 ID 全集；`ProposalIntegrityService` 新增 6 参 `check`，把投影 ID 并入本轮对账集；`AskOrchestrationService` 传入 `projection.assetIds()`。

**fail-closed 不变**：只认服务端结构化投影，不解析用户文本、不放宽到全清单；清单解析不到或策略未授权即丢弃；5 参 / 4 参兼容入口行为不变，非投影资产仍判 `ID_NOT_IN_SET`；execute 全链仍做清单 / 策略 / RLS 重校验。

## 7. 观察项（未闭环，如实登记）

- **O-1** runner 原始输出 `model=null`：runner 进程未加载 `.env.local`，模型名仅由服务端配置；本证据以服务端配置 + `llm_call_trace` 为准。待 runner 补环境变量透传（非阻塞）。
- **O-2** 题集 `t-turn-incremental-18` 的 `expected.terminal=query` 与 `degradedPathNote`（确定性降级路径 T2 允许澄清）口径不一致。本轮 LLM 路径输出 `query` 故 PASS；若走降级路径 runner v2.2 会误判。登记为题集判据待澄清项，**未擅自改判据**。
- **O-3** 编排层二次契约校验在 prime 清理后走无参词表并回退全量授权词表，而模型修复轮在 prime 期间用「收敛 + 投影」词表；两者口径不同（二次校验更宽松），属既有行为，登记为待统一项，本次未扩大改动。
- **O-4** 当日进度快照此前记录 `mvn clean test 710/0`，本轮 surefire XML 实测 `690/0`；口径差异可能为并行会话或统计范围不同，未回改历史行，按 append-only 登记。
- **O-5** 复测期间另一流程发布的不合法清单 `2026.11.12-twenty-first-r2` 仍以 `--ontos.manifest.startup-load=false` 绕过并运行时显式激活 v19，未改数据库。

## 8. 结论

1. 多轮继承的**服务端口径缺陷**已定位并修复：提示词要求「按投影合并完整语义」，但输出契约与完整性对账只允许本轮检索候选，两层互相打架。
2. 3 道探索性多轮题在修复后 **3/3**，单次运行、单轮次。
3. **不解除 ADR-0019 的 C-1，不替代 test 集 v5 全量 ×3**；是否把 `system-v4-draft.md` 升为正式提示词 v4、是否以复杂度子集替代原 C-1，仍待负责人终审（ADR-0022）。
