## 4. `t-existence-06` 根因与修复

### 4.1 现象

首轮模型输出被修复轮引导后落到澄清；服务端未执行 LOOKUP_BATCH。

### 4.2 根因

1. **异步契约候选缺失**：AgentScope 修复轮运行在 Reactor 线程，原 `SessionCandidateContextProvider` 依赖请求线程 ThreadLocal，拿不到本轮授权候选，误判 `property.customer.tier` 候选外。
2. **LOOKUP 属性完整性过严**：`批量查 c-1001、c-9999 的等级` 中的「等级」未稳定命中 property 检索候选，但该属性已通过输出契约授权词表。
3. **runner 判据缺口**：v2.1 对 `expected.identity` 只读单实体 `dsl.identity.value`，没有读 `LOOKUP_BATCH.dsl.identities`。

### 4.3 修复

1. `AgentContextProvider` 增加问题感知候选视图；`SessionCandidateContextProvider` 在 prime 时保存本轮授权候选快照，异步修复轮可还原本轮词表。
2. LOOKUP / LOOKUP_BATCH 的 `attributes` 在通过输出契约授权词表时允许进入完整性对账；聚合路径 metric / dimension / filter 仍严格限定检索候选。
3. runner 升 v2.2：`LOOKUP_BATCH` 使用 `dsl.identities` 对账，`expected.identity.value` 存在于批量列表即 PASS。
4. `IntentProposalContract` 修复问题感知词表下的 NPE。

## 6. 结论

1. 按阶段合并有效覆盖：RETENTION 3/3、ATTRIBUTION 4/4、LOOKUP_BATCH 2/2。
2. `ComplexAnalysisParamsResolver` 在 RETENTION / ATTRIBUTION / LOOKUP_BATCH 链路可用。
3. 该证据不是一次连续 9/9；不解除 ADR-0019 的 C-1，也不替代 test 集 v5 全量 ×3。
