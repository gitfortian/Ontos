## 3. 发现与处置

| # | 发现 | 级别 | 处置 |
|---|---|---|---|
| F-1 | `PolicySnapshotService.activate` 的 `catch (RuntimeException)` 把原始异常直接转为 `1003000007`，无日志——连接故障/死锁会被误报为「版本冲突」且丢失堆栈 | P2 | **已修**：catch 内补 warn 日志（含 tenant/version/异常摘要）；fail-closed 语义不变（异常仍抛出、事务仍回滚） |
| F-2 | 规格 §1「M4 保证策略版本进缓存键与审计」——审计已进（`policy_version` 列）；缓存键含的是**清单声明的** `policyVersion`（V1 published_snapshot 列），运行时生效快照版本未进键。因 `prepare` 先行无越权路径，属防御纵深缺失 | P2 | **已修**：`QueryCacheKey` 新增 `runtimePolicyVersion` 输入（`PolicyService.cacheVersion` 容错提供，dev/缺失记 none 占位），`SCHEMA_VERSION` 升 `cache-key-1.1`（旧键自然失配，符合 ADR-0008「字段只增、升版失效」）；新增单测 `shouldDifferByRuntimePolicyVersion` |
| F-3 | 规格 §3.1 写「Rule（布尔判定）判定点」且 asset_type 含 `rule`；实现按 METRIC 判定 `booleanMetricId`（种子将布尔指标登记为 metric 型），`AssetType.RULE` 枚举定义但无判定点使用 | P3 | **登记**：与 M3 冻结语义（布尔指标=指标，`booleanMetricId` 引用）自洽，判定点语义等价（checkIndividual 闸门已覆盖）；`RULE` 保留给未来规则引擎。规格文字下次升版时并入修正 |
| F-4 | 错误码码值与规格文字漂移：规格 §3.1 写「未授权报 1003000004」，实现为 `1003000005`（`_004` 分配给快照非法）；「label 拒绝 100100000x」实现为 `1_003_000_006` | P3 | **登记**：语义链（清单存在性→快照缺失/非法→资产未授权→label 个体拒绝）与规格一致，仅码值分配不同；码值已进测试断言与 rls-probe，下次规格升版统一改文字 |
| F-5 | 规格 §3.1「RequestContext 携带的策略版本与当前生效快照不一致时拒绝」未实现——RequestContext 无策略版本字段、无请求头通道。E1 验收口径（TTL 内收敛，E2E 实测 61s）已满足；M4 架构下每次请求实时判定、无会话内权限缓存，该条款针对的攻击面（编排缓存旧权限）在 M5 才出现 | P3 | **登记**：作为 M5 编排接入的前置条件——M5 引入会话内缓存/编排复用时必须绑定 policy_version 或维持每请求实时判定；网关版本下发契约归 M6/M8。进度快照同步登记 |
