## 2. 结论

**T1.3 判定：通过**（2 项登记，无代码缺陷）。

### 2.1 规格逐条对照

| 规格条款 | 实现 | 结论 |
|---|---|---|
| §1.1 事件锚点（不要求 metricId，独立分流） | `validate()` 在 metric 必填检查前分流 `validateRetention`；`validateMode` 返回 null | 符合 |
| §1.1 `timeRange.field` 由服务端按 cohort 事件 `timeProperty` 回填 | `resolveRetention` 取 EventDef.timeProperty 回填；客户端提交 timeRange 立即拒绝 | 符合（D-6 约束落实） |
| §1.2-1 cohort 起点 = 窗内首次事件 | `cohort_first` CTE `min(occurred_at)` 按主体聚合 | 符合 |
| §1.2-2 回访 = 后续周期内发生即留存 | `retained` CTE 逐期 `exists` 判定，不要求次数 | 符合 |
| §1.2-3 周期 = 自然周（周一）/ 自然月（1 日） | `date_trunc('week'/'month')` + 执行器固定会话时区 Asia/Shanghai | 符合 |
| §1.2-4 未完整周期排除 / 窗内无完整期整题拒绝 | `periodEnd <= today` 逐期过滤；`firstPeriod > latestComplete` 抛 `RETENTION_PERIOD_INCOMPLETE` | 符合 |
| §1.2-5 主体去重 | `count(distinct subject)` | 符合 |
| §1.2-6 Asia/Shanghai 左闭右开 | cohort 窗口 `>= from` / `< to`；周期边界 `[start, end)` | 符合（funnel 的 `<=` 右闭偏差不在本任务范围） |
| §1.2-7 维度取 cohort 时点主体属性 | cohort CTE 内 JOIN 主体表并随主体分组；非主体表维度拒绝 | 符合 |
| §1.1 输出行语义 | `cohort_period / period_index / [dims] / cohort_users / retained_users / retention_rate` | 符合 |
| §1.1 无除零路径 | `nullif(cohort_users, 0)`；cohort_users=0 的期无行 | 符合 |
| §3 负例必含六类 | Golden 覆盖 periods 越界 / 未发布事件 / 未完整期（单测）/ 事件级维度 / 客户端 timeRange / filters | 符合（绝对日期由 explicitRange 单测覆盖） |
| §4 性能样例（G-3） | dry-plan 成本：近 90 天 28.95 / 近 3650 天×12 期 86.72，闸门沿用 M2 `PLAN_COST_BLOCKED` | 符合（如实登记数据量小未触发阻断） |

### 2.2 安全与确定性边界

- **不新增身份面**：无新增身份来源；RETENTION 与 funnel 同为事件锚点，`prepareWith` 跳过 metric 主资产判定与
  路径规划（`isEventAnchored`），授权仍由维度 `DIMENSION` 策略判定承担（既有口径，未降低）。
- **物理名只来自清单**：事件判定列 / 时间列 / 主体列、维度列、主体属性列全部经 `OntologySnapshot` /
  `SemanticManifest` 解析；SQL 中唯一的 interval 字面量来自封闭枚举 `WEEK|MONTH`（`DSL.inline("1 " + unit)`）。
- **占位符**：全部 `?` 参数化（`ParamType.INDEXED`），无字符串拼接值；Golden 逐字比对锁定形状。
- **纵深防御**：编译器不依赖校验器顺序——自行复核 params / timeRange / 事件对 / 映射一致性，
  绕过校验器也不会静默编译。

## 3. 发现与处置

| # | 级别 | 发现 | 处置 |
|---|---|---|---|
| T13-1 | P3 契约 | **模式规格 v1.1 §1.1 的示例 DSL 用 `dimensions: ["dim.channel"]`，但同节定档「首发只支持映射主体表的已发布维度」，而清单 v11 的 `dim.channel` 映射 `orders`（非主体表 `customer`）**——示例照抄会得到 `RETENTION_DIMENSION_UNSUPPORTED` | **登记，不升版**：定档条款两处明确（§1.1 表 + 修订摘要 ②），示例属示意未随修订更新；升版会与冻结的 M6 规格 v1.0 引用链（已由 D-4 口径覆盖）叠加歧义，收益不抵成本。实现按定档执行，Golden 使用 `dim.customer_tier`（唯一主体表维度）；**下次模式规格升版时修正示例** |
| T13-2 | P3 性能 | `retained` CTE 是 `cohort × periods` 笛卡尔展开，主体规模大时中间结果放大 `periods` 倍（首发 periods ≤ 12）；当前 demo 数据（3 cohort 主体）成本 86.72 未触发阻断，真实规模未验证 | **登记**：随 M7 压测（W5/T5.1）给真实规模结论；若超阈值，优化方向 = 按 `cohort_period` 分桶限制 `generate_series` 上界（不改口径） |

**无 P1/P2 代码缺陷**。走查确认：客户端伪造 `timePatternId/timeParserVersion` 被解析器入口清空；
`explicitRange` 在校验器拒绝（即使解析器回填了 timeRange）；跨模式参数混用一律拒绝而非忽略。
