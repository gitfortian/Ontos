# 产品前端实施规格 深度审核 R1 v1（完整性与契约一致性视角）

> **类型**：审核
> **审核对象**：[产品前端 实施规格 v0.1](../../99-archive/plans/产品前端-实施规格-v0.1.md)
> **审核方法**：① 与后端真实契约逐项对照（AG-UI 事件形态 / `POST /ask/runs` 响应 / 澄清回传 / 事件重放端点）；② 完整性扫描（状态 / 边界 / 依赖）；③ 可执行性（任务依赖闭合、验收可测）；④ 与 M5 / M4 / A.4 既定约束对齐。
> **结论**：**13 项发现**（P1 × 4 / P2 × 6 / P3 × 3），采纳 11、拒绝 2；v0.1 **不通过冻结**，修订后升 v0.2。

## 发现与裁决

| # | 级别 | 发现 | 裁决 |
|---|---|---|---|
| F-1 | **P1 架构** | **「会话 ≠ 轮」模型缺失**：规格通篇混用 session（会话）与 run（轮）。真实语义：澄清回传产生**新 run**，一个 session 含多个 run；UI 会话流必须按 session 聚合、按 run 分段消费事件。不定义此模型，历史 / 重放 / 事件拼接全都会错 | 采纳：v0.2 新增 §4.1「Session–Run–Turn 三层模型」 |
| F-2 | **P1 架构** | **事件事实源未统一**：首问走 AG-UI SSE，澄清回传走 `POST /ask/runs`（同步终态，无流式）——同一会话流里两通道事件段无法拼接，且回传轮同样要跑模型（有过程可展示）。已核实后端存在幂等事件重放端点 `GET /ask/run/{runId}/events`（M5 R4/R5），可作统一事实源 | 采纳：v0.2 §4 改为「**run 事件流 = 唯一事实源**」：首问 AG-UI SSE、回传轮 / 断线续播走 events 重放（轮询或 SSE 化），UI 状态机消费同一事件模型 |
| F-3 | **P1 契约** | **澄清回传协议未定义**：`clarificationChoice` 后端为 String，前端拟传 `{choice: assetId}`——点选 / 默认建议 / 跳过降级三种意图如何编码、服务端如何校验（M5 R5 已有候选持久化 + 回传校验）未对齐 | 采纳：回传协议 v1 明细化 = 原样传 assetId（点选）/ `__default__`（默认建议）/ `__skip__`（跳过降级）；W-B3 与后端核对回传校验对三种取值的语义 |
| F-4 | **P1 契约** | **回传轮拿不到 runId**：`POST /ask/runs` 正常终态响应**不含 runId**（仅 waiting 态含），无法订阅 events 重放 | 采纳：新增后端小改——`POST /ask/runs` 响应统一回 `runId`（并入 W-B3） |
| F-5 | **P1 产品缺陷（现状实锤）** | **现 ChatPanel 每轮换 session**（`s-<requestId>`），指代消解 / 上下文继承 / 场景态在产品对话里全部失效——「那华南呢」这类多轮在产品里根本不工作。产品对话必须**每会话固定 session_id**（首问生成、全程复用） | 采纳：v0.2 §6.1 会话模型强制固定 session；Playwright E1 必须覆盖多轮指代用例 |
| F-6 | P2 契约 | 终态载荷在事件流中的确切位置与 schema 未定（CUSTOM 还是 RUN_FINISHED？字段形状？）——PoC #3 只验证「可重建」未固化 schema | 采纳：W0 spike 交付物增加「事件→终态载荷映射清单」 |
| F-7 | P2 功能 | 图表形状映射需要**列类型**（时间 / 文本 / 数值），查询结果行无列类型 meta——前端无法可靠区分线图 / 柱图 | 采纳：W-B 增加结果 meta 列类型（后端小改，从词典推导）；未落地前图表只做「维度 1 个 → 柱」保守映射 |
| F-8 | P2 安全 | **CSV 导出是批量导出面**：前端导出绕过 M2 批量安全闸门的语义（行数闸门在查询侧已有，但导出文件离开浏览器管控） | 采纳：**首版砍掉 CSV 导出**（登记 Backlog，随 M8 网关与审计策略定档） |
| F-9 | P2 一致性 | 治理后台入口的角色可见性未定义——业务用户不应看到失败看板 / 发布记录入口；前端需要 roles 感知（M4 上下文含 roles） | 采纳：登录态解析 roles → 导航按角色显隐；无角色信息时后台组隐藏 |
| F-10 | P2 可测性 | E1 的「10 类代表性问法」没有清单，验收不可执行 | 采纳：v0.2 附录 A 固化 10 问法清单（含多轮指代用例，呼应 F-5） |
| F-11 | P3 可测性 | W0 spike 缺评分表定义，「按分决策」不可执行 | 采纳：v0.2 补评分维度（重建完整度 / 定制成本 / 依赖健康度 / 升级风险，各 0–5） |
| F-12 | P3 交叉引用 | SSE 经 M8 网关的缓冲 / 心跳 / 超时未落到 M8 任务 | 采纳：§11 交叉引用改为「M8 网关任务清单显式含 SSE 透传」 |
| F-13 | P2 开发者视图 | retrieval 词表域是排障关键信息，开发者视图应展示当前生效域与词表规模 | 采纳：开发者视图增加「候选域 / 词表规模 / 对账口径」状态行 |

## 拒绝项（留痕）

| 提议 | 拒绝理由 |
|---|---|
| 会话历史支持删除会话 | 与审计一致性冲突（audit_log 只追加）；列 Backlog 由合规定档 |
| 消息编辑 / 撤回 | 非目标已声明（§1）；问数的轮次语义不适合编辑重放 |

## 审核结论

v0.1 的骨架（决策点 / W 包 / E 判据）成立，但**通道架构（F-1/F-2）与会话模型（F-5）属于地基级缺陷**，必须在 v0.2 重写 §4 与 §6.1；另需补后端配套任务（F-3/F-4/F-7）。修订后升 v0.2，进入 R2。
