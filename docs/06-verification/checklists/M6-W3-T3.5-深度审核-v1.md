## 3. 发现与处置

| # | 级别 | 发现 | 处置 |
|---|---|---|---|
| T35-1 | P2（尝试后否决） | 「渠道」话术歧义（concept.channel 实体 + dim.channel 维度）——曾尝试 v17 把 concept.channel 移出场景 roots，被**场景 allowedRelations 端点校验**拒绝（`ontology.Order.attributedToChannel` 端点必须落在 rootConcepts 内——ADR-0004 归因关系一条不减） | 否决 v17 路线；维持 concept.channel 在域内，歧义消解改由 T35-2 优先级语义承担 |
| T35-2 | P2 | **模板命中被资产级歧义淹没**：规格 §7.5 序列上澄清（4/5 步产物）先于 VQR（第 7 步），初版 planner「澄清优先」——用户话术完整命中人工审核模板时，仍被「渠道是实体还是维度」的资产级歧义打断 | planner 顺序调整：**VQR 完整命中（全串匹配 + 参数提取成功）优先于澄清**——模板已消歧（维度/口径在模板内定死），与 T24-4「入口级语义优先」同一原则；命中后仍走 execute 全链重校验（不是绕过校验的捷径）；真服务复验命中 PASS |
| T35-3 | P2 | **模板缺时间维度声明导致执行失败**：query 模式相对时间解析要求 `timeRange.field`（时间维度资产 ID），VQR 模板只有 time_expression_raw → execute 报「缺少 timeRange.field」 | 模板词表增 `time_dimension` 键（资产 ID 引用 → timeRange.field）；v16 模板与测试 fixture 补齐；VqrValidator 依赖集自动覆盖该键（资产引用校验生效） |
| T35-4 | P3 登记 | E2E「越权命中」判据在 demo 租户级快照下不可构造（无用户差异化授权） | 判据以机制单测承载（同形拒绝/伪造 ID/绑定失败）；用户/行级差异化授权的 E2E 归 M4 策略细化或测试环境造数 |
| T35-5 | P3 登记 | 模板匹配是字面全串匹配（不支持同义词/语序变体）——命中率受限于 questionPattern 编写质量 | 候选召回增强（别名/语序/向量）属 §7.5 第 8 步高级召回范畴，归后续阶段 |
