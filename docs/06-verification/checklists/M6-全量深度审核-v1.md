## 3. 代码级复核要点（三路交叉 + 本人复验）

- **W1 构造器**：`SqlCompiler` 分流 83-109；FUNNEL 时间窗唯一入口 `analysisParams.cohortWindow`（`DslValidator` 277-280 拒顶层三通道），顶层 filters 同时进 cohort 与每步 CTE（478-486 / 519），值经 `condition()` 参数化（1358-1369）；`DSL.inline` 仅用于封闭白名单 interval/unit，非用户值。RETENTION/ATTRIBUTION 顶层 `timeExpressionRaw` 由 `TimeWindowResolver` 回填并拒客户端 timeRange（132-148），validator 复核回填产物（441-445 / 527-530）——D-7 补了 raw 必填断言。
- **W2 场景**：三态封闭迁移（`ScenarioRouteState` 31-34）、REJECT 不 fallback、错误码同形（不存在/未发布/未授权均 1004000003，防存在性泄露）、scope 纯交集（`ScenarioScopeService` 110-121）、运行时无 catalog 草稿表依赖。**D-1**：`adjudicate` 原在 ④ 落状态，⑤⑦⑥ 与 `prepareWith` 后续失败均留 `in_scenario`；已拆为纯校验 + `commitExplicitRoute`（prepare 全链成功后）。
- **W3 Skill/VQR**：`SkillRegistry.byId/carriersFor` 只读 published；capabilities 在运行时 `ControlledCapabilities` 校验（发布期未校验，登记 D-22）；VQR 命中全串匹配 + in_scenario 引用集收窄；`executeVqr` 唯一出口 `execute(dsl)` 零旁路；integrity 对账在编排层（v1 报告「RunState 对账」措辞不精确 → D-20）；cache-key-1.2 含 tenant/userScopeHash/policy/内容哈希，缓存命中仍先 prepare。
- **W4 复合**：JGraphT 显式环检测 044、resultRef 闭枚举与 EQ 约束（`DslValidator` 1132-1173）、注入值只进绑定、无依赖/有依赖双路径结构化失败、空结果不注入空值；D-4 补 dependsOn 重复的结构化拒绝。
- **W5 评测/看板/运维**：V17 表 + 五维白名单聚合 + 租户过滤 + fail-closed 登记、前端真消费 dashboard API、保留策略默认永久、池 16 均属实；评测 runner 的宽松判据与证据链缺陷见 D-8～D-18。
