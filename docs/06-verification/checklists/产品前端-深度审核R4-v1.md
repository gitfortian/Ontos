## 1. 总评

规格 v1.0 的**产品形态与交互骨架扎实**（R1/R2 已补齐通道模型、状态机、安全红线），但本轮从「能不能照着做」查下去，**5 项 P1 全部集中在「规格声称依赖的东西仓库里不存在或与现状互斥」**：

1. **D1 主路线与唯一事实源是两套 run 空间**（H-1）——最重，会让 M5 已验收的安全能力失去落点；
2. **身份模型三处互斥**（H-2）：现状「网关注入 + localStorage + UI 不做登录」、D3「前端登录页」、D7「不写任何 Web Storage」；
3. **七条验收判据依赖未引入的工具链**（H-3，Playwright）；
4. **性能预算与真模型事实冲突**（H-4，首字 ≤2s vs 实测 8s）；
5. **W-B2 被估成「≤2 天小改」，实为引入认证机制**（H-5），且 token 驻留无规则。

**结论：规格不需重写，需一次「落地性补版」**——采纳 11 项并入 v1.1，v1.0 归档；不新增产品功能，只补前置依赖、契约落点、判据口径与决策点。

## 3. 逐项展开

### H-1（P1）D1 主路线与「唯一事实源」是两套 run 空间

**事实**：规格 §4.2 定义「首问 `POST /ask/runs` 拿 `runId` → 订阅 run 事件，传输形态由 D1 定（AG-UI SSE 或 events 轮询）」，把 AG-UI SSE 当成同一条 run 的传输选项。实查（B-1/B-2/B-9）：
- `streamAgui` 打的是 AgentScope 原生 `/agent/run/ontos`，**runId 前端生成**，走 AgentScope 自己的事件流；
- `POST /ask/runs` 与 `GET /ask/run/{runId}/events` 是业务编排通道，runId 是 `ask_run.run_id`（服务端 UUID，V14）；
- 两条通道在现有前端**并存于两个面板**；M5 已验收的会话锁（R3）、幂等重放（R4/R5）、澄清回传校验（R5）、WAITING_APPROVAL 状态机**全落在 ask_run 这一侧**。

**影响**：若 W0 选 A（CopilotKit Headless 直连），产品对话跑在 AgentScope 原生流上——`runStateService.require` 归属校验、`afterSeq` 幂等重放、审批跨标签页轮询（G-11）、澄清候选绑定（R5）**全部失去落点**，等于用首版产品换掉 M5 验收过的安全骨架；R2 G-1「服务端唯一裁决」在原生流上需重新证明。R1 F-2 统一了「事件流」概念，但**未核实两条 run 的实体关系**——这是残留架构缺口。

**裁决（并入 v1.1）**：① §0 D1 增硬约束：**所选路线必须复用 `ask_run` 事件流；A 路线须由服务端 bridge 把前端 AG-UI runId 映射到 `ask_run.run_id` 并落 `ask_run_event`，否则不得选 A**；② §10 评分表加一票否决项「通道归属可行」，不通过即选 B；③ W0 交付物增「runId 映射与通道归属决策」；④ §4.2 明确 AG-UI SSE 与 events 重放只能是**同一 ask_run** 的传输差异，不得引入第二套 run 空间。

### H-2（P1）身份模型三处互斥

**事实**（B-7）：现状 `request.ts` 用 `localStorage` 存 tenantId 并注入 `X-Ontos-Tenant`，注释明确「身份来自可信网关，UI 不拥有登录跳转」，401 文案也是「检查网关身份注入」。而 D3=a 要做**前端登录页**、W-B2 要签发 token；D7（R2 G-2）又规定「**不写任何 Web Storage**」。三者不能同时成立：token 写 localStorage 违反 D7；只放内存则刷新掉登录；多标签页（G-11 审批轮询）拿不到共享登录态。

**影响**：W8/W-B2 开工时才发现要改 D7、改 D3 或改全部 API 身份注入——都是跨模块改动，不能编码期临时决定。

**裁决（并入 v1.1）**：新增 **D10「身份 SSOT 与登录态驻留」**，建议：
- **身份唯一入口仍是服务端**：登录页只提交凭据，服务端签发 `httpOnly + Secure + SameSite` cookie（不写 Web Storage、刷新可恢复、多标签页天然共享），网关校验 token 后按现状注入 `X-Ontos-*` 头——**业务代码与 PoC/基线脚本零改动**；
- 退路「内存 token + 静默续期」，但须补刷新恢复与多标签页同步用例；
- 无论哪条，**移除 `TENANT_STORAGE_KEY` 的 localStorage 读写**，D7 四条细则不破。

### H-3（P1）七条判据依赖未引入的 Playwright

**事实**（B-8）：E1/E2/E3/E4/E6/E7/E9 证据列全是 Playwright，W9 写「≥20 用例入 pnpm 基线」，E10 要求基线全绿；但全仓无 Playwright，`ontos-ui/tests/e2e` 仅 README 占位。[R3 F-7](产品整体规划-深度审核R3-v1.md) 亦把「T4.3 浏览器 E2E 需先引入 Playwright」登记为未闭环项——**前端规格把它当既有能力用了**。

**影响**：W9 才引入会带来依赖/浏览器二进制、CI runner、`pnpm check` 挂接三类隐性成本，且 W2–W8 期间任何 E 判据无法中途验证，问题全堆到收口期。

**裁决**：新增 **W-E0「E2E 工具链引入」**，与 W0 并行、W9 前置；交付物 = 依赖 + 浏览器安装 + 一条冒烟用例跑通 + 基线挂接。

### H-4（P1）性能预算与真模型事实冲突，E6 不可测

**事实**：§7 冻结「首字 ≤2s；500 行表格首渲染 ≤500ms；TTI ≤3s」，E6 用 Playwright trace。但「首字」未定义（模型首 token？UI 进度指示？）、未区分确定性/LLM 路径；E-7 实测真模型单次 ask **约 8s**（B-10）。若指模型首 token，LLM 路径 E6 **必然 FAIL**；若指 UI 反馈，2s 门槛 trivial 且与模型无关。

**影响**：判据要么永远不过、要么测了个无意义的东西；R3 决策批 D-B（关 MemoryConsolidator）还会改变延迟基线，规格未联动。

**裁决**：拆两条——**硬门槛**「用户可见首个反馈 ≤2s」（提交后本地即时进度指示，不含模型）；**观测项**「模型首 token / 完整终态延迟」记录不作 FAIL 门槛（R-3 温度不可控）；E6 **固定用确定性降级路径或协议桩**，真模型延迟归 [SLO 与成本预算 v1](../evaluation/SLO与成本预算-v1.md) 与 E-7，口径不得混用（与 R3 D-A 同源）。

### H-5（P1）W-B2 是「引入认证机制」，不是 ≤2 天小改

**事实**：§4.3 把 W-B2 写成「签发 M4 认证上下文 token；roles 扩展 dev；401 对齐」并归入「各 ≤2 天」。实查：仓库**无用户凭据存储、无 token 签发/校验 filter、无登录端点**，M4 `RequestContext` 由网关注入头构造；新增登录要动凭据存储、密码校验、签名/过期/续期、全端点 filter、前端 http 层、401 语义，以及**所有 PoC / live 基线脚本现用的 `X-Ontos-*` 头**；token 驻留规则另缺（H-2）。

**裁决**：W-B2 拆 **W-B2a（认证机制 + 基线脚本兼容）** / **W-B2b（roles `dev` + workspace 隔离联动）**；删除「≤2 天」硬估，改「W-B2a 先出设计核对再排期」；token 驻留归 D10。

### H-6（P2）E5「15 个高频码」与清单 12 条模板

**事实**（B-6）：v19 清单 `copyTemplates` = 12 条；`CopyTemplateService` 只从清单取模板，未命中回退 `GENERIC`。E5 要求「15 个高频码全有中文文案」，W6 只写「15 码文案盘点」——**没列 15 个码，没说缺的 3 个谁补**，走 GENERIC 算不算「有文案」也未定义。

**裁决**：W6 补「15 码清单（标注：专属模板 / GENERIC 兜底 / 缺口需资产升版）」；E5 判据改「15 码均有中文可读文案且无 `{x}` 占位符透出」，缺口如实登记，不静默放宽。

### H-7（P2）会话标题数据源与「input 不展示」互斥

**事实**（B-4/B-5）：`ask_run` 无 utterance 列；`RUN_STARTED.input` 才含首问原文（服务端只抹身份键）。§5 写「`RUN_STARTED` input 不展示、不上报（A.4）」，但 §6.2 `SessionList` 标题要「首问前 24 字截断」——前端订阅事件流即收到含 utterance 的 payload；开发者视图（D8）沿用事件日志组件，会直接展示 `input.utterance` 与 `clarificationChoice`，与 A.4 冲突。

**裁决**：§6.2 明确「W-B1 仅允许为生成标题读取首问 utterance，对话流其余位置不展示 input；开发者视图展示事件日志前对 utterance/回传值二次脱敏或默认折叠」；W-B1 响应只回标题，不回完整 input。

### H-8（P2）W-B4 列类型落点未定，冲击表格性能预算

**事实**：`TerminalAssembler.query` body 只有 `rowCount`/`rows`，前端 `AskTerminalVO.body` 同样无 columns。W-B4 写「结果 meta 增列类型」但没说加在终态 body 还是 `planRef` 的 `/api/v1/query/plan/{id}`。若走后者，每张结果卡多一次请求，与「500 行表格首渲染 ≤500ms」冲突。

**裁决**：W-B4 明确「在 query / composite 终态 body 内联 `columns: [{key, valueType, unit}]`」，前端零额外请求；`planRef` 仅用于开发者视图回放。

### H-9（P2）W0 未挂钩 PoC #10 硬闸门

**事实**：roadmap M0 冻结「PoC #10 未通过前前端工程不启动」；M6 验收把 CopilotKit spike 登记为附条件项。规格 W0 叫「渲染路线 spike」且是首任务，但**没写「W0 即 PoC #10 正式执行并关闭该附条件项」**——两处台账可能互认对方负责。

**裁决**：W0 交付物增「PoC #10 闸门关闭证据（20 会话记录与结论）」；§11 登记「W0 通过 = 附条件项关闭」。

### H-10（P2）E1 十类问法的模型依赖未定

**事实**：附录 A 十类问法含澄清点选、审批批准/拒绝、复合意图、多轮指代；E1 用 Playwright「全链走通」。真模型实测通过率 32%（单轮全量）/ 66.7%（定向 30 题）且**波动 ±10%**（B-10）——跑真模型用例必然 flaky，且每次 CI 消耗真实 token（与用户明确的成本敏感冲突）。

**裁决**：E1–E4 **固定使用确定性降级路径或协议桩**（与 R3 D-A 的「评测配置纪律」同源但用途不同：此处是 UI 回归，不是效果评测）；真模型只用于 E-7 ×3 轮评测，两类证据不得互相引用；E1 用例集须标注所用路径。

### H-11（P3）E9/E10 口径——**拒绝**

**初判**：E9「Playwright ≥20 用例入 pnpm 基线」与 E10「verify-baseline 全绿」看似两套基线。
**复核**：`scripts/verify-baseline.mjs` 的 7 项中第 2 项即 `pnpm check`（11-11 live 实跑 20.2s）；Playwright 用例一旦挂进 `pnpm check`，E10 天然覆盖 E9。**结论：不构成不一致，属审核误读，撤销**；仅在 v1.1 §9 E9 补一句「挂 `pnpm check`，由 verify-baseline 间接覆盖」作为口径澄清（不改变判据）。

### H-12（P3）依赖图错误

**事实**：§8 W0 依赖列写「无」，但 W0 评分维度含「多轮全可重建」，而回传轮 runId 依赖 W-B0（B-3：正常终态响应不含 runId）——**W0 实际有前置**。W-B 行整体只标「D3/D4」，但 W-B0（runId 回显）、W-B4（列类型）与登录/历史无关。

**裁决（部分采纳）**：W0 依赖改「W-B0」；W-B 行按任务分别标依赖（W-B0 → D1/W0；W-B1 → D4；W-B2 → D3/D10；W-B3 → W3；W-B4 → W4）。
