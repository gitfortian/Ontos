## 2. 方法与环境

- 本地 PG18（`ontos` / `ontos_queryds`），Spring Boot 以 `local` profile、`--server.port=8080`、`--ontos.agent.enabled=false` 启动；`/actuator/health` 由启动中的 `OUT_OF_SERVICE` 转为 `UP` 后再执行评测。
- 复跑命令：`node scripts/verify/smoke-runner.mjs --base-url http://127.0.0.1:8080`。
  runner 对 20 题中「确定性链路已上线」的 14 题逐题打真实 `/api/v1/query/dry-run`（复合题走 `/composite/execute`），每题唯一 `X-Request-Id`；
  依赖 LLM 编排 / 会话 / discovery 的 6 题按 [评测统计口径 v1 §2](../evaluation/评测统计口径-v1.md) 记 `skip`，**跳过不算通过**。
- 证据固化：把 runner 输出的 `-latest` 软名结果逐字固化为 [零号冒烟-评测证据-v1.json](../evaluation/零号冒烟-评测证据-v1.json)，
  不改任何字段；复算其整文件 SHA-256 并登记于 §6。
- 哈希可复算：独立重算 gold 文件哈希、题目文档哈希、gold 数组的 `contentHash`（键排序 + 紧凑 JSON 的 SHA-256，
  [统计口径 v1 §5](../evaluation/评测统计口径-v1.md) / D63 修复语义），与证据 `setHashes` 及 gold 内嵌 `contentHash` 四方比对。

## 4. 失败案例与归因

- **0 fail、0 error**：本次无失败用例，无环境故障。
- **6 条 skip（不算通过）**：`#13` 口径澄清、`#15` 用户文本改租户、`#16` 提示注入拒绝、`#17` 能力边界、`#19` 多轮指代、`#20` discovery，
  均依赖 M5 会话/意图编排与澄清拒答装配（runner 已逐题写明）；`#15/#16` 的 RLS/注入底层防线另由 `rls-probe.mjs` / E5 对抗探针覆盖，但不计入本评测分子。
- **runner 自述口径缺口**：拒绝类题目当前判定为「业务错误码拒绝且非 500」，错误码与 gold `reasonCode` 的精确映射待 M5 接线后收紧，已在 runner 注释与证据 JSON 双登记。
- **未闭环欠账（不阻塞本次最小框架验收，但阻塞 M7 整阶段验收）**：
  1. `test` 集 **0 题**（§13.2 建议正式验收至少 200 题），主指标目前只能报 dev/validation 并显式声明；
  2. `scenario_entry_mode` / `scope` / `frozen_calibers` / `turn_type` 分层字段缺口（归 M5 / M6 / M7 收敛）；
  3. 消融、失败看板、追踪、性能与安全压测全部未启动；
  4. 14 个有效样本属小样本，Wilson 下界 0.7847，不足以支撑 §13.5 的「相比基线达到预设百分点提升」。

## 5. 结论（有条件通过）

**最小框架三件验收通过，且有条件**：三件交付物与 M4 规格 E6 三条判据全部满足，证据可复算、可复现；
条件是把 §4 的四类欠账如实带入 M7 收敛，不得把本次 14/0/6 或「成功率 100%」当作 M7 正式评测结论。

- 本记录**不是 M7 阶段验收报告**；M7 全量交付物仍按 roadmap「M6 后收敛」推进，`OBL-M7` 状态维持 `deferred`。
- M4 收口时，E6 的 OBL-M7 核对项可直接引用本记录与 §6 证据，无需重复执行评测（但若清单、题目集或 runner 版本变更，必须重跑并升版本）。
- 触发阶段由 M4 改为 M6 的决策与理由见 [ADR-0015](../../01-decisions/ADR-0015-M7最小框架验收与触发阶段重定.md)。
