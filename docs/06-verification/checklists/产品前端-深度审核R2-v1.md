# 产品前端实施规格 深度审核 R2 v1（用户视角 / 攻击者视角 / 产品高标准）

> **类型**：审核
> **审核对象**：[产品前端 实施规格 v0.2](../../99-archive/plans/产品前端-实施规格-v0.2.md)
> **审核方法**：① 攻击者视角（回传伪造 / 驻留泄露 / 越权呈现）；② 真实用户旅程逐帧走查（含异常帧：断网 / 超时 / 长会话 / 并发标签页）；③ 产品高标准核查（空态 / 文案 / 防误读 / 可达性）；④ 与 M5 会话锁、M4 脱敏、A.4 红线对齐。
> **结论**：**14 项发现**（P1 × 3 / P2 × 7 / P3 × 4），采纳 13、拒绝 1；修订后 **v1.0 冻结**。

## 发现与裁决

| # | 级别 | 发现 | 裁决 |
|---|---|---|---|
| G-1 | **P1 攻击者** | **澄清回传可伪造**：前端点选回传的 assetId / 自定义文本可被任意篡改（DevTools / 重放）——若服务端仅做白名单匹配而无绑定校验，攻击者可诱导结果指向非用户意图资产 | 采纳：规格红线「**前端输入一律不可信，服务端唯一裁决**」显式写入 §7；E1 用例增加回传伪造帧（篡改 assetId 必须被回传校验拒绝，M5 R5 已冻结该能力，本用例是回归证明） |
| G-2 | **P1 驻留泄露** | **敏感结果驻留面比 D7 描述的大**：bfcache（前进/后退缓存）会把含敏感行的页面整体驻留；多租户切换不清态会把 A 租户结果展示给 B 租户用户 | 采纳：D7 细化为四条——不写 Web Storage；`pagehide`/`unload` 不做敏感数据持久化；登出 / 租户切换强制清内存态并跳登录；注册 `pageshow` 事件检测 bfcache 恢复时强制刷新会话态 |
| G-3 | **P1 状态机** | **会话锁只有一句话，没有状态机**：`idle→composing→running→…` 的转换规则、输入禁用矩阵、WAITING_APPROVAL 时能否继续浏览历史、重连恢复时状态如何回放都未定义——这是产品交互的骨架 | 采纳：v1.0 §6.1 补完整状态机表（状态 × 允许动作 × 输入区行为 × 恢复规则） |
| G-4 | P2 引导 | 示例问题的「discovery 通道生成」含糊——discovery 返回的是资产清单，不是可点击的自然语言问法；需要「资产→问法模板」的生成规则 | 采纳：W6 细化——按指标模板生成（如 `{指标名}按{维度}统计` 取首个 allowedDimension），静态兜底 3 条 |
| G-5 | P2 防误读 | 图表规则缺**负值 / 全零**处理：销量退款类指标可为负，零基线柱图对负值语义不同；全零数据画柱图是空图 | 采纳：v1.0 图表规则补——含负值时柱图显示正负分离并标注；全零只给表 |
| G-6 | P2 性能 | 虚拟滚动只是提法，没有验收口径——200 轮长会话的滚动帧率与内存必须有判据 | 采纳：E6 增加「200 轮会话滚动无可感知卡顿（无长任务 >50ms）」 |
| G-7 | P2 语义 | 「停止跟随」与状态机 running 的交互未写清：停止后 run 仍在服务端执行，用户再次发送会撞会话锁（M5 R3）——UI 必须在停止后仍禁输入至 run 终态到达 | 采纳：v1.0 状态机表明确「stopped-following 仍属 running，输入保持禁用，终态经重放补全」 |
| G-8 | P3 呈现 | discovery 三组全空时的文案卡与「查看可查资产」入口形成死循环（入口又回到 discovery） | 采纳：空能力时文案改为「当前清单无可查资产，请联系管理员发布」且不带入口 |
| G-9 | P3 历史 | 会话列表标题规则未定 | 采纳：首问前 24 字截断为标题 |
| G-10 | P2 恢复 | 断线重连后 UI 状态恢复规则未写：`afterSeq` 续播是「补发全部缺失事件」还是「从当前态快照重建」，流式文本已渲染部分不能重复拼 | 采纳：v1.0 §4.2 明确——重放按 seq 去重、文本增量按 `messageId` 幂等拼接（与后端重放幂等判据对齐） |
| G-11 | **P1 一致性** | **WAITING_APPROVAL 的跨标签页语义缺失**：审批在 `/approvals` 页操作后，对话页的审批卡如何得知（轮询？事件？）——用户在两个标签页操作同一会话是真实场景 | 采纳：v1.0 §4.2 补——对话页对 waiting_approval 态的 run 定时拉取事件（5s 间隔轮询），审批完成后自动恢复；多标签页并发以服务端 run 状态为唯一裁决（前端不乐观更新审批结果） |
| G-12 | P2 呈现 | 复合结果分组卡的「部分失败」呈现未定义（G-6 044–046 失败码族）——部分失败是产品核心卖点（可解释），UI 必须把成功子结果与失败子原因同屏 | 采纳：v1.0 composite 卡规则——失败子卡展示 copy_template 渲染的原因 + 成功子卡照常呈现，不整体报错 |
| G-13 | P3 工程 | 卡片级错误边界缺失：单张结果卡渲染崩溃会拖垮整页 | 采纳：每张终态卡包 ErrorBoundary（降级为错误卡 + 重试） |
| G-14 | P3 工程 | dev 角色来源未定：token roles 如何表达 `dev`（M4 角色词表扩展）未登记 | 采纳：登记 W-B2 附带项——roles 词表扩展 `dev`；无该角色时开发者视图入口隐藏 |

## 拒绝项（留痕）

| 提议 | 拒绝理由 |
|---|---|
| 消息编辑 / 撤回 | 非目标（§1）；问数轮次语义不适合编辑 |
| 会话分享链接 | 涉及敏感结果的越权访问面（分享链接绕过租户上下文），与 A.4 / M4 冲突；列 Backlog 由安全定档 |

## 审核结论

v0.2 已补齐架构地基（R1 的 P1 全部落地）。R2 的三个 P1（回传伪造红线 / 驻留泄露面 / 会话锁状态机）均为「高标准产品」的必要条件，修订后升 **v1.0 冻结**；两项决策依赖（D1 spike、D3/D4 后端配套）在冻结态内允许按 §0 建议执行。
