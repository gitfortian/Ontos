## 1. 范围与方法

**代码范围**：`ontos-module-query` 全部生产代码与测试、V5/V6 迁移、`ManifestActivationListener` 端口与异步装配、
`ontos-ui/apps/web/app/ask/dsl-panel.tsx` 与 `service/query`、`scripts/verify/` 四个证据脚本、`ontos-assets/` 清单版本链。

**方法**（四条并行，避免「只跑单测就算审过」）：

1. **规格逐任务对照**：按实施规格 §4 的 W1–W6 任务表与 §6 的 E1–E8，逐条确认代码落点与证据；
2. **fail-closed 边界审查**：重点看「输入驱动 500」「静默丢语义」「静默错数」三类——
   它们不会被正常路径的单测发现，却直接违反确定性系统的前提；
3. **真实库攻击性验证**：PG18 + 租户 `demo` + 生效清单 `2026.11.08-seventh`，用刻意构造的畸形/越界 DSL
   逐项复现（下文每一项都有修复前的真实返回码）；
4. **证据复跑**：Golden / 复合 / RLS / 对抗四类脚本在新构建上重跑，确认修复没有改变既有判定。

**与验收报告的关系**：《M2 验收报告 v1》保持冻结不改。本文件记录其后的复核与修正；
修复不改变判定——E1 仍为「可构造子集 27/27 逐字一致」，E2–E8 复跑全部通过（§4）。

## 2. 结论

- 共 **12 项发现**，全部已修复并在真实库复验：3 项 500（D50/D51 输入驱动，D54 清单误配）、
  2 项静默错数（D58 的 YOY_MOM 与 FUNNEL 分支）、1 项 SQL 报错（D49）、1 项部署时区依赖（D56）、

- **R-18 关闭**：模式授权前移到路径规划之前，规则型指标不再被误报为 `PATH_UNREACHABLE`。
- **M2 判定不变：通过（E1 附条件，ADR-0013）**；`mvn test` 254 → **269 例全绿**，四类证据脚本复跑通过。
- 新增残留风险 1 项（R-25 时间列展示口径，归 M3）；R-16 维持。

## 3. 发现与处置

| # | 现象（修复前真实返回） | 级别 | 根因 | 修复 |
|---|---|---|---|---|
| **D49** | YOY_MOM + 跨表维度（`order_count × dim.customer_tier`）返回 `1002000003`；PG 报「对于表 customer，丢失 FROM 子句项」 | 高 | `compileYoyMom` 从不展开 `resolvedJoins`：校验器按 Join 覆盖放行了跨表维度，编译器却只 FROM 指标表 | 抽出 `addJoins`，在 YOY 的聚合 CTE 与维度枚举 CTE 同时展开；Golden `g-y0x` 形状不变 |
| **D50** | YOY_MOM 缺 `analysisParams` → 500 `NullPointerException: params is null`；`analysisParams:{}` → 500（`Set.of(...).contains(null)`） | 高 | `validateAnalysisParams` 对 null 直接 return；`YOY_MOM_PERIODS.contains(null)` 抛 NPE | 校验器要求 `analysisParams` 与 `period` 必填；编译器补纵深防御，两处均按 `DSL_INVALID` 拒绝 |
| **D51** | `timeExpressionRaw="近 99999999999999999999 天"` → 500 `NumberFormatException` | 高 | `Integer.parseInt` 未兜底，超长数字直接冒到 Spring | 捕获后按「未命中模式」处理 → `1002000008`；并设 N 上限 100000（≈273 年） |
| **D52** | QUERY 夹带 `entityId/attributes/identity/identities/identityPropertyId/booleanMetricId` 返回 `code=0`（字段被静默丢弃）；复合容器同形 | 中 | 校验器只在 lookup 分支消费这些字段，聚合分支既不用也不拒 | `rejectLookupOnlyFields` 在聚合入口一律拒绝；`validateComposite` 补齐 `identityPropertyId/booleanMetricId` |
| **D53** | 多步骤 funnel 的后续事件映射到不同属性时，仍按首事件的时间列/主体列/判定列编译（当前唯一清单两张事件同构，属潜在静默错数） | 中 | 校验器逐事件检查「非空 + participantClass 一致」，未检查事件之间映射一致 | 校验器与编译器都要求所有步骤事件共享同一物理映射，否则 `FUNNEL_EVENT_MAPPING_MISSING` |
| **D54** | 清单规则表达式 `metricId` 写成数字时，lookup 触发 `ClassCastException` → 500（发布校验未覆盖 rule.expression） | 低 | `(String) expression.get("metricId")` 强转 | 改为 `instanceof String` 判断 → `RULE_EXPRESSION_INVALID`；校验器同处一并修 |
| **D55** | `POST /compile` 响应没有规格 §3.2 要求的 `mode`；`cost` 也未返回 | 中（规格偏差） | 响应 VO 未随 M2 扩展 | 补 `mode`；`cost` 维持只在 dry-plan 提供（compile 做 EXPLAIN 会让 compile 与 dry-plan 重复，并把成本闸门副作用带进编译通道）——口径记入 §5 |
| **D56** | QUERY 时间窗用 `Timestamp.from`（JVM 默认时区墙钟）绑定，而 funnel/yoy_mom 用上海墙钟；在非 Asia/Shanghai JVM 上同一时间窗偏移 8 小时 | 中 | 两套时间绑定口径并存 | `timeCondition` 统一 `shanghaiTimestamp`；单测以「绑定值的墙钟 == 上海本地时间」钉死，不依赖 JVM 时区 |
| **D57** | YOY_MOM 允许把 `timeRange.field` 自身放进 `dimensions`，编译成「按日展开、月值重复」的错位结果 | 低 | 校验器只查维度授权，未查时间维度与 period 的职责冲突 | `DSL_INVALID` 拒绝（时间口径由 period 承担） |
| **D58** | YOY_MOM 带 `filters` 时 SQL 里没有过滤条件（`gmv × region` 与全量结果同形）；FUNNEL 带 `filters` 返回 `code=0` 但完全忽略 | 高 | 两个构造器都没有接 filters 的位置，校验器也未拒绝 | YOY_MOM 把过滤同时下推到聚合与维度枚举（含跨表 Join）；FUNNEL 明确拒绝（M2 未定档，不用「看起来成功」糊过去） |
| **D59** | 只编译过的产物回放显示「未估算成本 · 成本 0 / 行数 0」 | 低 | `QueryPlan` 的成本/行数是基本类型默认 0，回放未 EXPLAIN 时也透出 | 控制器按 `planJson == null` 判定「未估算」，成本/行数返回 `null` |
| **D60** | 复合容器设置 `limit` 被子意图默认值覆盖（静默丢弃客户端设置） | 低 | `toChildDsl` 未搬运 limit，`validateComposite` 也未校验容器 limit | 容器 limit 校验范围后下放给每个子意图；单测断言编译入参 `limit=20` |

**附：R-18 关闭**（验收报告中的残留风险，非新发现）

原实现 `prepareWith` 先 `joinPathResolver.resolve` 再 `dslValidator.validate`：规则型指标（无物理表）走 QUERY，
规划器先报 `PATH_UNREACHABLE`，把「模式不支持」误报成「路径不可达」。现将「指标存在 + 模式授权 + 模式已实现」
抽成 `DslValidator.validateMode`，在路径规划前调用；实测 `metric.high_value_customer` + QUERY 返回
`1001000004 指标不支持该分析模式`，并有服务层单测钉死。

## 5. 规格偏差与口径说明

1. **`POST /compile` 不返回 `cost`**：规格 §3.2 的接口表把 cost 列在 compile 扩展字段里，
   但这与 §3.2 自身的「dry-plan = 编译 + EXPLAIN、compile 只编译」冲突。实现取后者：
   compile 不触 EXPLAIN（避免同一请求两次取计划、避免把成本闸门带进编译通道），
   cost 只在 dry-plan / dry-run 返回。`mode` 已按规格补齐。**建议下次规格升版时修订该字段说明**。
2. **funnel 不接受 filters**：analysis-mode 规格 v1 未给 funnel 过滤定档，步进 CTE 也没有对应位置。
   M2 采取显式拒绝而不是静默忽略；支持归 M6（与漏斗结果编排同批）。
3. **YOY_MOM 不接受时间维度作为分组维度**：时间口径由 `analysisParams.period` 承担，
   两者并存会产出「按日展开、月值重复」的错位结果，按 fail-closed 拒绝。
4. **复合容器 limit 是「每个子意图的上限」**：子意图没有独立 limit 字段；容器级值统一下放。
