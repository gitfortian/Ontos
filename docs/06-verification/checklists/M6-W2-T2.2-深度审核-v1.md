## 3. 发现与处置

| # | 级别 | 发现 | 处置 |
|---|---|---|---|
| T22-1 | **P2** | **旧清单兼容**：直接把 `ontologyScope` 改成对象会让 v12 的数组反序列化失败（或静默丢 scope），历史清单无法加载 | 两个 scope 加 delegating creator：数组→`rootConcepts`/`metrics` 并标记 legacy；v12 结构校验与回装测试继续通过 |
| T22-2 | **P2** | **状态双写漂移**：记录的 `status/version/owner` 在列上，definition 里也有一份；单元测试捕获 draft 记录的 definition.status 仍是 published | 服务每次写库前 `syncDefinition`；JDBC 仓储同样以列为真源覆盖 definition |
| T22-3 | **P2** | **回滚版本格式错误抛 500**：非 SemVer 版本触发 `IllegalArgumentException`，不是业务错误 | 改为 `SCENARIO_VERSION_INVALID`（1_005_000_008），补测试 |
| T22-4 | **P2** | **发布未校验记录与 definition 的 ID 一致**：构造错配记录可发布到别的资产 | publish 前置校验 `record.id == definition.id`，不一致按 `SCENARIO_INVALID` 拒绝 |

| T22-6 | P3 | v13 的 skills / vqrs / coldStartSamples 为空 | W3（T3.1/T3.4）扩展段落地后填充；当前校验对非空引用会 fail-closed，不会假通过 |
| T22-7 | P3 | JDBC 仓储无集成测试（生命周期单测用内存仓储） | T3.6 资产运营页接控制器时补真实库读写测试；当前 DDL 与映射已编译验证 |

## 5. 复核口径

- **历史清单不是「能解析就行」**：必须同时过结构校验，且回装不丢生命周期键；legacy 分支只放宽生命周期字段，不放宽引用完整性。
- **管理面不碰运行时**：catalog 只写生命周期表，运行时仍只读清单；`ArchitectureTest` 已强制。
- **回滚不改线上**：回滚只改管理表为草稿，清单重新发布前线上仍读旧版本。
