## 2. 设计边界（三点必须留痕）

1. **D4 证据外置的边界落法**：catalog/清单校验器**不持有任何数据源连接**，条件 3–6 只验引用非空（goldenRef / resultCheckRef）。证据内容由 catalog 之外的流水线产生并归档（当前引用格式 `golden:<asset>#<case>` / `e2e:<script>#<case>`，格式校验留给 T3.5 命中通道与 M7 评测接线收紧）。
2. **运行时权威 = 清单**：失效经发布流水线生效（下一版清单移除）；两次发布间的窗口期 drift 由八步重校验兜底（VQR 命中组装 DSL 后走既有 execute 全链——T3.5 接线）。catalog 状态由运营跟进 retire，ontology 不回调 catalog（ArchUnit 边界保持）。
3. **不兼容变更的保守判定**：新旧清单中同一资产的定义 JSON 任何不一致都视为不兼容（宁误杀不放过）；Skill 另有主版本升级 + 结构字段（analysisMode/paramsSchemaRef/requiredCapabilities/allowedScenarioIds/approximationOf）变化判定。误杀的代价是 VQR 提前失效（可回滚重审），漏杀的代价是错误口径上线——方向正确。
