## 1. 要回答的问题

附录 A 锁定主路线为 **shadcn/ui + Tailwind v4 + Radix + CopilotKit Headless**，并把它列为 PoC #10。
判据里有一条硬约束：**不得引入 `/api/copilotkit` 类 Node runtime**，否则违反 §1.2.1「单体应用」锁定。

所以 T5.5 要回答的不是「CopilotKit 好不好用」，而是：

> CopilotKit Headless 能否**在不引入 Node runtime 的前提下**，直接消费 Java 后端的 AG-UI SSE？

## 2. 执行方式

| 项 | 值 |
|---|---|
| CopilotKit | `@copilotkit/react-core@1.85.0`（`/v2` 入口，Headless） |
| AG-UI 客户端 | `@ag-ui/client@1.0.2`（与 CopilotKit 依赖对齐；1.0.3 会因两份 `AbstractAgent` 声明导致类型不兼容） |
| 注入方式 | `<CopilotKitProvider agents__unsafe_dev_only={{ ontos: new HttpAgent({ url: "/agent/run/ontos" }) }}>`，**不配置 `runtimeUrl`** |
| 验证页 | `/probe/copilotkit`（独立页面，不动产品 `/ask`） |
| 后端 | 单 jar，`POST /agent/run/ontos` 提供 SSE |
| 浏览器 | 真实 Chromium（Playwright），记录全部网络请求 |

## 3. 结果

| 项 | 结果 |
|---|---|
| 页面挂载 | **通过**（`CopilotKitProvider` 在不配 `runtimeUrl` 时正常工作） |
| 会话跑通 | **通过**：3603 ms 返回 370 字符的完整 JSON 意图提案，`terminal: "query"`、`metric_id: "metric.gmv"`、`dimensions: ["dim.region"]` |
| `messages` 同步 | 通过：`user` + `assistant` 两条 |
| **`/api/copilotkit` 请求** | **0 次** |
| 其他 Node runtime 请求 | 0 次 |
| `/agent/run` 请求 | 1 次（直连成功） |
| UI 错误 | 无（仅一个 404 静态资源，与本链路无关） |

**协议层结论：CopilotKit Headless 可以在零 Node runtime 下直连 Java AG-UI SSE。**

## 4. 但入口不是生产级的

实现方式依赖 `CopilotKitProvider` 的 `agents__unsafe_dev_only` 属性。这个名字本身说明了三件事：

1. **不是官方推荐的生产用法**——字段名里带 `unsafe_dev_only`；
2. **可能被移除或改签名**——属内部/实验性 API，升级时有断裂风险；
3. **缺少配套能力**——鉴权头、thread 生命周期、错误重试这些在 runtime 代理模式下由框架代劳的东西，直连模式下要自己补。

换句话说：**技术可行性成立，产品可用性未成立。**

## 5. 结论：主路线有条件成立，但不建议现在切换

| 维度 | 判定 |
|---|---|
| 协议可行性 | **成立**：零 Node runtime 直连成功，事件正常 |
| 生产可用性 | **不成立**：依赖 `unsafe_dev_only`，无稳定 API 承诺 |
| T5.5 判据「给出主路线 / 退路结论」 | **建议走退路**：保持 `@ag-ui/client` + 自研 shadcn 渲染层 |

理由：

- 当前 `/ask` 页已用 `@ag-ui/client` 等价能力（自研 `stream()` + shadcn 渲染）跑通 20/20 会话与流式时序，**退路已经实证可用**；
- CopilotKit 带来的增量价值主要是「预置交互抽象」（生成式 UI、HITL 组件），而这些在 M1 才用得上；
- 为了一个 `unsafe_dev_only` 入口，把主链路的稳定性押在一个随时可能变的 API 上，风险与收益不匹配。

**处置**：CopilotKit 列为「观察项」，M1 复查它是否提供正式的 non-runtime 接入方式（例如官方 `HttpAgent` 直连文档化的 Provider 用法）。若届时仍只有 `unsafe_dev_only`，正式采用退路并更新附录 A 的表述（发 ADR，不原地改附录）。

## 6. 对 ADR-0001 的影响

ADR-0001 里 T5.5 写的是「等 PoC #10 结论后接入」。本次结论是**不接入**，属于对该条的落地回答，不改变 ADR-0001 的其他决策（组件层仍是 shadcn/ui + Radix，包管理仍是 pnpm）。

已在 ADR-0001 追加「T5.5 结论」记录，决策内容未变。
