## 2. 已执行项的要点

### 2.1 通过项（#2 / #7 / #1）

- **#2**：3 个独立 JVM（含 2 次重启）× 100 次编译，规范化 SQL 与绑定值逐字一致率 **100%**，系统级关闭。
- **#7**：4 类攻击 × 25 trial + 200 条正常样本。现行 §4.8 建议初值 FAIL（50 次泄露），
  按 [ADR-0002](../../01-decisions/ADR-0002-跨轮差分规则修订.md) 修订后泄露 0 / 误报 0。探针级，M4 集成复验。
- **#1**：5 组用例 × 100 次，越权 0。3 项未运行（索引命中、策略版本入审计、pgbouncer 池）依赖环境与 M4 能力，
  已由负责人签字接受「限定范围通过」，登记 M4 补验。

### 2.2 未通过项（#3）

四项判据里三项达标（artifact 坐标、Boot 4.0.1 兼容、破坏性 API 差异清单），
第四项「五类结构化终态 20 次会话重建 100%」未达标：

| 指标 | 结果 |
|---|---|
| JSON 可解析 | 100% |
| 落到五类终态之一 | 100% |
| 与期望终态一致 | 68.8%（11/16） |
| 界面侧复验（另跑 20 次） | 20/20 一致 |

两批结果差异来自模型输出的批次间波动（逐条核对原始数据，两侧都没判错）。
卡点已从「框架能力」转到「模型对输出契约的遵循度」，解法是服务端程序化校验 + 重试，属 M1。

另：判据自身有两处表述与实测不符（`streamEvents()` 不存在、skill/toolkit API 未被移除），已在 PoC-03 §5 记录。

### 2.3 部分通过项（#4 / #10）

- **#4**：QUERY 模式 20/20 逐字一致、参数零拼接、真实 PG `EXPLAIN` 20/20 通过；
  但 5 种分析模式只实现了 1 种，且曾**非 QUERY 模式静默生成聚合 SQL**（高危）。
  **处置（2026-11-07，M0 内）**：已按报告建议实现编译层 fail-closed——校验器与编译器双层显式拒绝
  非 QUERY 模式（错误码 `1_002_000_006`，含 2 个新单测），静默错查路径关闭；其余模式构造器实现仍待 M2。
- **#10**：纯浏览器直连 Java AG-UI SSE 成立（零 Node runtime）；界面重建 4/6 类事件
  （`STATE_*` 与 HITL 需 M1）；`RUN_STARTED.input` 明文回显用户原问，前端脱敏未实现。
