## 背景

PoC-07（探针级，4 类攻击 × 25 trial + 200 条正常样本）实测出三个问题，均指向 §4.8.2 的可判定性：

1. **累计阈值对「首次精确差分」天然无效**。`differential_pair` 权重小于 `T`，第一次命中后 `risk < T` 必然放行；两轮即可反推个体值（`20 行 − 19 行 = 那 1 个 VIP 的 salary`）。实测 100 条攻击中 **50 条泄露**，判据要求 0。
2. **规格 §7 给的退路「阈值下调」单独不可行**。把 L1 阈值降到 4 能堵住首次差分，但正常用户第 4 次同类查询即被转审批，**误报 25%**，与 ≤2% 判据互斥。
3. **三处规则字面歧义**按最宽解释实现会必然撞破误报率判据（详见决策 2）。

结论：这是**规则缺口**，不是阈值调参问题。按文档规范，技术选型 v1.1 已冻结不得原地改，故以本 ADR 冻结 §4.8.2 的生效解释。

## 决策

以下四条自本 ADR 冻结起生效，与 §4.8.2 原文冲突处以本 ADR 为准。

### 1. 精确差分改为即时动作（阻断项）

`differential_pair` 中满足全部下列条件的子情形，**命中即转审批**，不再经过 `risk ≥ T` 比较：

- 层级为 L1；
- 与同层**上一条已记账事件**相比，`filters` 集合差恰为 1；
- 两个结果集存在包含关系（`R_prev ⊇ R_cur` 或 `R_cur ⊇ R_prev`）；
- 结果集基数差**恰为 1**；
- 两个结果集基数均 **> 1**（基数 ≤ 1 走决策 3，不重复判定）。

动作：停止返回个体值，转 `approval_request`，`reason_code = SENSITIVE_QUERY_SEQUENCE`，全量审计；两层独立判定，任一层命中即触发，不做 `risk` 相加。

**未命中上述子情形的 `differential_pair`（基数差 2 至 `k−1`）保持 §4.8.2 原有权重与累计口径不变。**

### 2. 三处解释性约束显式化（阻断项）

| 约束 | 生效解释 |
|---|---|
| 差分对的包含关系 | 「`filters` 集合差恰为 1 且基数差 < `k`」**还须**结果集存在包含关系。仅条件相邻但结果不相交（如 `region=华东` → `region=华南`）不计差分对 |
| 连续收窄的基数 | 「连续 ≥3 次收窄」路径要求首末基数**严格下降**且结果集包含；「基数不变、仅条件反复变化」的正常多轮分析不计收窄。相邻两次的「基数非增」判定保留原意 |
| L1 个体值 | `result_cardinality ≤ 1` 的 L1 查询**直接转审批**，不进入累计计数路径。这是 §4.8.3「停止返回个体值」与「正常返回仍按 10.5 脱敏」共同蕴含的约束，不是新增策略 |

### 3. 阈值保持 §4.8.1 建议初值

L1 / L2 / L3 的 `T` **不下调**。下调阈值与「误报 ≤2%」判据在实测中互斥（决策 1 已替代该退路）。

**禁止任何实现以「把 T 调小」代替本轮修订**：该做法在探针中实测误报 25%，且会随真实业务分布进一步恶化。

### 4. 记账口径

- 命中即时动作的请求**仍写入 `sensitive_query_event`** 并计入后续累计。理由：否则攻击者可无限次触发精确差分而不升级，形成审批疲劳，且无法自动收敛到拒答档位。
- 被**拒答**或**硬阻断**的请求未执行查询，不记账、不计入累计（与 §4.8.2「仅对窗口内已过期事件累加」一致）。
- `pattern_tag`、所属层级、`risk`、规则版本照旧写入审计，保证可回放；即时动作分支额外记录命中的判定分支标识。

## 依据

- PoC-07 三档对照实测（同模型、同数据源、仅规则不同）：

  | 档位 | 精确差分处理 | 泄露 | 正常误报 | 结论 |
  |---|---|---|---|---|
  | 现行初值 | 计累计权重 | 50/100 | 0% | FAIL |
  | 退路 A | 仅下调阈值 | 0 | 25% | FAIL |
  | **退路 B（本 ADR）** | 命中即转审批 | **0** | **0%** | **PASS** |

- 三档在跨会话拦截（25/25）、存在性探测硬阻断（25/25）、两层不累加、窗口过期、文案唯一性上一致通过，说明修订未牺牲其他判据。
- 完整指标与失败判据清单见 [PoC-07 原始输出](../06-verification/poc/PoC-07-raw.json)。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 维持 T=8 与纯累计权重 | 实测 50% 泄露，直接违反 §7 #7 判据 |
| 只下调阈值（退路 A） | 误报 25%，与 ≤2% 判据互斥；且随业务分布恶化，无稳定工作点 |
| 保留 `differential_pair` 字面最宽解释 | 「条件相邻但结果不相交」全部计入差分对，正常维度切换被误判 |
| 直接改技术选型 v1.1 §4.8.2 | 违反文档规范「冻结不可原地改」，且会使已归档的 PoC 依据失去锚点 |
| 精确差分命中即**拒答**（而非审批） | 正常用户的合法下钻（如按地区→按地区+渠道）会被直接拒答，代价过高 |

## 影响

- **M4 实现约束**：跨轮判定必须实现即时动作分支与三处解释约束，不得只做累计计数；`sensitive_query_event` 需能记录判定分支标识以支持回放。
- **技术选型 SSOT**：§4.8.2 的**生效解释**由本 ADR 承载，技术选型 v1.1 正文不动。下次升版（v1.2）时必须并入本节四条，并入后本 ADR 在「修订记录」标注「已并入」，编号不复用。
- **判据不变**：§7 #7 的通过标准不因本 ADR 放宽；本 ADR 只改「怎么实现才能达标」。
- **闸门影响**：本 ADR 是 G1 解除的阻断项之一（另一项为 `#1` 限定范围通过的签字），完成后 M0 硬阻断结论升 v2。

## 回退方案

若 M4 集成复验（真实业务分布）发现即时审批的误报率超出判据，可回退为「即时**告警** + 单次强制脱敏」而非直接审批，但：

- **不得回退到纯累计权重**——已实测 50% 泄露，属判据硬失败；
- 回退须发新 ADR 取代本 ADR，并在进度中记录触发回退的实测数据。
