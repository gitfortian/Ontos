# ADR-0013 · Golden 集 v2 不可构造案例的处置口径

> **上游依据**：[M2 实施规格 v1.0 §6 E1](../03-plans/stages/M2/M2-确定性编译与执行内核-实施规格-v1.md)、[技术选型 v1.1 §7 #4](../02-solutions/architecture/智能问数系统技术选型方案-v1.1.md)、[ADR-0011 决策 5](ADR-0011-M2实施规格状态修订.md)、[M2 验收报告 v1 §4](../06-verification/checklists/M2-验收报告-v1.md)

## 背景

M2/W6 回填 Golden 集 v2（30 条）时，有 3 条案例在真实资产上**无法构造出可编译的请求**，
与「实现有缺陷」不同，它们是案例与环境/定档的冲突：

| 案例 | 现象 | 根因 |
|---|---|---|
| `g-f04` | 编译拒绝 `1002000023 funnel 维度必须属于主体实体: dim.region -> customer` | 案例设计（M2/T1.2）早于 analysis-mode 规格 v1 的定档（funnel 维度限主体实体）；`dim.region` 属 orders 表，主体是 customer |
| `g-n02` | 期望 `1001000005 维度不在指标允许范围`，但该错误在真实清单上不可触发 | R-01 修复（清单 v4 起 6 个指标各补 5 个维度）把维度授权放全，负例失去可构造条件 |
| `g-n05` | 期望「实体跨授权域被拒」，实际不拒 | local profile 为 `dev-allow-all`；真实域策略要等 M4 网关接入 |

## 决策

1. **案例集保持原样**：`Golden集-v2-案例设计.json`（v2-cases）与 `Golden集-v2-gold-v1.json` 均不改写。
   理由：评测集「边做边改」是本项目明确列出的风险（roadmap R7），为了迁就实现对已冻结判据做改判，
   会让「效果可证明」这件事本身失去意义。
2. **E1 判定口径**：E1 = 「**可构造子集 27/27 逐字一致（SQL 字符串 + Join 路径 + 负例错误码）**」。
   3 条不可构造案例按下列方式接替，**不计入 E1 分子也不计入分母**，但在验收报告 §4 逐条留痕：
   - `g-f04` → 由 `FunnelValidatorTest#shouldRejectDimensionOutsideSubjectEntity`（funnel 维度限主体实体）接替；
   - `g-n02` → 由 `DslValidatorTest#shouldRejectDimensionOutsideMetricWhitelist`（维度授权闸门）接替；
   - `g-n05` → 登记 M4：域策略接入后由 M4 的跨域探针接替，届时若仍不可构造再评估。
3. **M2 放行 M3**：E1 记「附条件通过」，附条件的关闭条件即本节第 2 条的三个接替项均已存在（现均已存在）。
4. **后续阶段再遇不可构造案例**：沿用本 ADR 的三步——先判「是不是实现缺陷」，再判「是不是案例与定档冲突」，
   两者都不是才按环境限制登记归属阶段；**禁止**为让案例通过而放宽校验器或私自改判据。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 改判案例并升版（g-f04 维度改主体维度、另两条标注接替） | 能让 E1 字面 100%，但要动已冻结的评测集；改判据的收益是「数字好看」，不是「系统更可信」 |
| 为 `g-n02` 保留一个窄授权指标（发清单 v8） | 为了让一条负例可构造而故意把授权配窄，与 R-01 的修复方向相反；且 g-f04 仍要改判，收益不完整 |
| 判 E1 不通过、M2 不予放行 | 3 条均非编译器缺陷，同族判据已有单测或其它案例佐证（`g-f03`、`g-n01/n03/n04/n06` 全部实拒通过），据此阻断整个阶段不成比例 |

## 影响

- 《M2 验收报告 v1》E1 行沿用「附条件通过」，状态冻结；roadmap M2 记「已通过（E1 附条件，见本 ADR）」。
- `Golden集-v2-gold-v1.json` 的 `unsupported` 三条即本 ADR 的登记对象，后续脚本重跑会稳定输出同样分类。
- M4 需在域策略落地后回填 `g-n05`；M3 不涉及本 ADR。

## 回退方案

若后续认为必须让 E1 字面 100%，动作顺序为：① 复核 `g-f04` 是否应改判（属案例问题，走案例升版 + 新 ADR）；
② 复核 R-01 的授权是否放得过宽（属清单问题，发新清单而非改校验器）；③ 只有前两者都不成立时，
才考虑调整 E1 判据本身——且必须新发 ADR，不得原地修改本文件。
