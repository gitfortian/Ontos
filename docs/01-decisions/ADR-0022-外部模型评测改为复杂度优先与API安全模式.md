# ADR-0022 · 外部模型评测改为复杂度优先与 API 安全模式

> **状态**：草稿（API 安全模式与复杂度子集准备即刻生效；是否以复杂度子集替代原 C-1 全量 ×3，待负责人终审）
> **版本**：v0.1
> **类型**：决策
> **负责人**：项目负责人（2026-11-12 指出「外部订阅 API 会被限制，重点测问题复杂度，性能测试没必要」并确认停止外部全量任务）
> **最后更新**：2026-11-12
> **适用范围**：E-7 / C-1 的外部模型评测执行方式、外部 API 保护、性能压测与外部模型的边界；不改变 M7 已冻结验收报告中已成立项，也不单方面宣告 C-1 通过
> **上游依据**：[M7 实施规格 v1.2 §4 W2 / §6 E3](../03-plans/stages/M7/M7-评测对抗防线与可观测-实施规格-v1.2.md)、[ADR-0019](ADR-0019-M7有条件通过E7评测挂账.md)、[SLO 与成本预算 v1](../06-verification/evaluation/SLO与成本预算-v1.md)、[E7 复杂度子集 v1](../06-verification/evaluation/E7复杂度子集-v1.md)、[R3 决策建议 D-A/D-B](../06-verification/checklists/产品整体规划-深度审核R3-v1.md)
> **修订记录**：2026-11-12 v0.1 初稿：停止外部模型全量 ×3；固化外部 API 安全模式与复杂度子集；保留原 C-1 口径待终审

## 背景

1. M7 原冻结口径中，C-1 要求 test 集 v5 全量 276 题 ×3，用于 E-7 / E3 的 LLM 路径验收。
2. 2026-11-12 先后尝试 GLM 与 mimo 的全量 ×3。两次均出现连续外部模型超时、本地 60 秒取消或编排层降级；负责人认为该方式会被订阅 API 限制，且重点应是问题复杂度而非性能压力。
3. 现有 `llm-test-runner.mjs` 原先默认并发 4、结束时才写证据文件，一旦中断，正式证据不可复原；缺少请求间隔、熔断、断点续跑和执行前确认。
4. M7/W5/T5.2 的性能证据已经使用本地 OpenAI 协议桩与确定性链路取得；外部模型不应继续承担吞吐/延迟压力职责。

## 决策

### D1 · 外部模型只做复杂度诊断

- 外部模型评测目标是判断模型在复杂问法、多轮上下文、时间推理、过滤、lookup、复合意图、澄清、能力边界与安全边界上的表现。
- 成功指标是**通过率、失败归因、分层覆盖与 token 消耗观测**。
- 不再用外部订阅 API 做吞吐、并发、rps 或延迟压测；P95 / rps 不作为外部模型评测门槛。

### D2 · API 安全模式成为 runner 硬约束

`llm-test-runner.mjs` 升级为外部 API 安全模式：

1. 默认并发 `1`；并发大于 1 必须显式传 `--allow-unsafe-concurrency`，仅允许本地协议桩使用。
2. 默认请求间隔 `2000ms`，可用 `--min-interval-ms` 调整。
3. HTTP `429`、HTTP `5xx`、网络错误、客户端超时与 waiting 超时计入连续失败；默认连续 3 次熔断。
4. 编排层连续 `degraded` 默认 8 次熔断，避免模型故障时继续消耗外部 API。
5. 每题结果立即写入 `${OUT}.checkpoint.jsonl`；`--resume` 可断点续跑，配置指纹不一致必须拒绝。
6. 默认只输出执行计划；真实请求必须显式追加 `--confirm`。
7. 计划必须显示题数、任务数、HTTP 轮次数、并发、间隔、熔断阈值、证据与 checkpoint 路径。

### D3 · 复杂度子集 v1 作为诊断入口

- 使用 [E7 复杂度子集 v1](../06-verification/evaluation/E7复杂度子集-v1.md)：50 题 / 57 个 HTTP 轮次。
- 子集从 test 集 v5 分层抽取，覆盖 QUERY、YOY_MOM、FUNNEL、RETENTION、ATTRIBUTION、LOOKUP、LOOKUP_BATCH、COMPOSITE、DISCOVERY、多轮、改口、差分、注入、跨域与场景入口。
- 该子集用于快速发现模型能力缺口与失败族，先 ×1。
- 其结果**不自动替代**原 C-1 全量 ×3。

### D4 · 原 C-1 口径暂不静默变更

- ADR-0019 的 C-1 仍然保持未闭环。
- 若负责人决定以「复杂度子集 ×1」或「降低运行次数」替代原全量 ×3 作为正式验收，必须将本 ADR 终审为已接受，并在 M7 验收报告 v2 中声明口径变更与局限。
- 在该终审前，任何子集结果只能作为诊断证据，不能写「C-1 通过」。

### D5 · GLM / mimo 中途运行降级为探索性证据

- GLM 约 300/828 与 mimo 约 820/828 的中断运行只保留 trace / 归因线索，不作为正式 C-1 证据。
- 后续引用时必须标注「外部 API 中断、无完整 runner 终局 JSON、非冻结口径」。

## 依据

1. 外部订阅 API 的配额、限流与稳定性不由本项目控制，持续并发会造成非被测系统故障污染被测结果。
2. E-7 关心的是模型语义与编排能力；性能与可用性已有本地协议桩口径。
3. 全量 ×3 的费用高、时间长，且已经暴露连续超时；继续原方式会浪费额度并产生不可解释的失败。
4. runner 中断丢证据的问题已在 2026-11-12 实际发生，必须用增量 checkpoint 修复。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 继续 GLM 全量 ×3，从已完成题增量续跑 | 模型锚点仍是 GLM 时可技术上续跑，但 GLM 延迟高且负责人已要求停止；跨模型拼接会使 C-1 口径失真 |
| 将 mimo 已跑约 820 题视作第 1 轮，再补 2 轮 | runner 被中断、无终局 JSON，且中途策略变化；不能伪造完整冻结证据 |
| 并发 2～3 折中提速 | 仍会放大外部 API 压力，违背「重点复杂度、保护订阅 API」的负责人指示 |
| 只用 30 题旧定向集 | 缺少 FUNNEL / RETENTION / ATTRIBUTION / 场景入口与安全边界覆盖，复杂度代表性不足 |

## 影响

- **正面**：外部 API 消耗可控；失败更可能反映模型/编排问题而不是压测伪影；中断后可续跑；正式口径不被混入探索性数据。
- **负面**：在负责人终审前，C-1 仍不能关闭；复杂度子集的置信区间小于全量 ×3，只能用于诊断和优先级排序。
- **对 M7 报告 v2**：报告必须同时写清「原 C-1 未闭环」与「复杂度诊断证据」两类口径，禁止互引为验收。

## 回退方案

1. 若负责人要求恢复原 C-1 全量 ×3：使用 mimo 锚点、API 安全模式、并发 1、`--confirm` 与 checkpoint；先冻结额度和窗口，再分批执行。
2. 若本地部署或专用无限制模型端点可用：可在本 ADR 终审后恢复并发评测，但仍保留 checkpoint 与熔断。
3. 若复杂度子集无法代表正式需求：回到 test 集 v5 全量，或由负责人另定新的正式子集并升版。

## 后续动作

1. 用复杂度子集 v1 输出计划，待负责人确认额度后再执行。
2. 根据子集结果整理失败族，回填失败看板与资产/提示词优化项。
3. 负责人终审本 ADR：若接受 C-1 口径变更，升 v1.0 并同步 M7 验收报告 v2；若不接受，保留全量 ×3 为唯一正式路径。
4. workspace 记忆隔离仍按 R3 D-C 单独立 ADR-0020，不在本 ADR 内替代。
