# ADR-0025：数据源凭据加密存储方案

| 项 | 内容 |
|---|---|
| 状态 | 已接受（2026-11-13） |
| 类型 | 安全决策 |
| 负责人 | 数据模型交付负责人（定档：AES-GCM + 环境变量密钥） |
| 适用范围 | `ontos-module-datasource` 注册配置凭据；不影响当前查询库的 yml 配置与执行链 |
| 上游依据 | B2 数据源插件化实施规格 §7（Phase 2 前半）；AGENTS.md §4 fail-closed |

## 1. 背景

B2 Phase 1 的数据源页只读浏览单个 yml 配置的查询库；Phase 2 前半开放「注册数据源」，
连接凭据（密码）需要落库。凭据落库即进入备份/日志泄露面，必须在存储层加密。

## 2. 决策

1. **算法**：AES-256-GCM（`AES/GCM/NoPadding`），随机 12 字节 IV，密文格式
   `Base64(iv || ciphertext)`；同明文两次加密密文不同（IV 随机）。
2. **密钥**：master key 为 Base64 编码的 32 字节 AES 密钥，经
   `ontos.datasource.master-key`（**环境变量注入**）提供；**永不落库、不进代码**。
   `application-local.yml` 中的开发 key 仅覆盖本地开发库凭据（与 `PGPASSWORD=123456`
   同级的既有本地惯例），生产必须显式注入随机 key。
3. **fail-fast / fail-closed**：
   - key 已配置但非法（非 Base64 / 长度 ≠ 32）→ **启动期抛异常拒绝启动**；
   - key 未配置时 encrypt/decrypt 一律抛 `1_006_000_109`——不降级明文；
   - 密文篡改/错 key → GCM 校验失败抛 `1_006_000_110`。
4. **存储分离**：`datasource_config.config`（JSONB）只存非敏感字段；secret 字段按插件
   descriptor 的 `secret=true` 声明剥离，合并 JSON 后整体加密存 `secret` 列；明文凭据
   不进库、不进日志、不出服务（视图层永远掩码）。
5. **编辑语义**：secrets 缺省 = 保留原密文（前端凭据留空）；提供则重新加密。
6. **注册闸门**：注册/编辑强制「测试连接」通过才落库（不可注册不可达的源）。

## 3. 后果

- 正向：凭据泄露面收敛到「master key + 数据库」双要素；密钥可独立轮换（重加密为 Phase 2 后半项）。
- 代价：key 丢失 = 已存凭据不可恢复（需重新注册）；跨环境迁移需带 key。
- 执行链零改动：业务查询仍走 yml 当前查询库；datasetId 化执行为 Phase 2 后半。
