## 1. 背景

B0 影响分析 §0.3 发现完整方案（v1.4 §5.1）是四层，其中 **Model 层**（逻辑数据集 / 事实粒度 / Join Path / SQL 方言）被 B0 三层化省略；§11 D-3 定档「Model 层为非目标、不预留空段」，触发点 = 首次多事实表同指标或第二种 SQL 方言。B1 D1 同时定档「物理层形态 = 数据视图资产，`Property.column → viewId + column` 为 P2」。B2 Phase 2 前半已落地数据源注册（ADR-0025）。

负责人 2026-11-13 定调：**主动借鉴 OpenBKN 的「数据源与建模完全拆开」（双网络 + 单一绑定点）思想，这是产品走向成熟的必要**——据此把上述触发点从「被动出现」改为「主动建设」。

## 2. 决策

1. **引入「数据视图」资产层**（`data_view` 表 + 清单 `dataViews` 段），作为 OpenBKN「数据资源知识网络」的 Ontos 对应物；语义建模（Property）改为 `viewId + column` 引用，**建模面不再直持物理表名**。
2. **这不是完整 Model 层**：只引入 Model 的「逻辑数据集」子集（单表/单视图镜像 + 列快照）。**事实粒度声明、Join Path 声明、SQL 方言三面维持 B0 D-3 的触发点纪律不变**——B0 D-3 的结论未被推翻，是启动条件从「问题出现」改为「负责人决策」，范围严格限定在逻辑数据集子集。
3. **视图生命周期 = 资源事实即时生效 + 发布快照进清单**：视图不走语义资产四态（draft/reviewing/published/retired 的语义审核流），用 active/retired 两态；运行时确定性由「合成发布时快照进不可变清单」保证。
4. **E1 SQL 逐字等价为迁移主判据**：`viewOf(viewId).table` 与旧 `tableOf(column)` 对同一属性产出相同字符串（B0 同款可构造性证明）；Golden 三份迁移前后逐字比对 0 差异，破坏即回滚。
5. **按 ADR-0014 口径登记偏离**：本决策属「主动提前建设」而非「事后追认」——触发点变更在实施前登记，不是事后改计划。

## 3. 后果

- 正向：建模与资源两个角色域彻底拆开（连接轮换/换库不影响语义资产）；为 Phase 2 后半 datasetId 化执行提供唯一前置；与 OpenBKN 的架构对齐降低后续互操作与认知成本。
- 代价：清单新增 dataViews 段（体积 KB 级可控）；迁移触及编译链 13 处同源点与 cohort 路径，需 Golden 逐字回归；视图列漂移的管理（重扫描提示）本期为半自动。
- 不变：执行链只读编译产物、清单不可变、E1 冻结口径、Mentions 语义检索、M2/M3 全部冻结行为。
