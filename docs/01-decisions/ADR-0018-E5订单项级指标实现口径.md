## 背景

[ADR-0016](ADR-0016-品类维度与订单事实指标的粒度边界.md) 已定档：首发**不提供**「品类维度 × 订单事实指标」查询，运行时 fail-closed `1002000014`（`PATH_GRAIN_EXPANSION`），并把实现口径留给 M7 二选一——① 新增订单项级指标；② 定义订单级去重语义。

M7 实施规格 v1.0 决策 1 定档 **方案 A（订单项级指标）**。实施前核对代码与数据结构事实：

1. Query DS `order_item` 表列为 `id / tenant_id / order_id / product_id / quantity / price`，**无 `amount` 列**；
2. 指标模型（`semantic.metrics`）只有 `table / column / aggregation / allowedDimensions`，**不支持表达式**（无法表达 `quantity * price`）；
3. 路径规划器支持**反向遍历**（`OntologyPathPlanner` reverse），且 `JoinPathResolver` 按遍历方向翻转基数（`order_item → orders` 为 N:1）——订单项指标经 `orders` 取时间窗不会粒度扩散；
4. test 集两题哨兵 `t-agg-single-17` / `t-yoy-06` 的题面是「各品类**订单数**」，方案 A 不能使其可编译（订单级指标 × 品类仍扩散），只能作为 fail-closed 负例。

## 决策

1. **新增订单项级指标 `metric.order_item_quantity`**：
   - `table=order_item`、`column=quantity`、`aggregation=SUM`；
   - `allowedModes=["QUERY","YOY_MOM"]`；
   - `allowedDimensions=["dim.product_category","dim.order_date"]`（首版只放开品类与时间；区域/渠道路径未验证前不放开）；
   - 语义：按订单明细行统计的商品销量（件数），**订单项口径**，与订单级 GMV / 订单数 / 客单价 / 客户数分列。
2. **品类维度只允许与订单项级指标组合**；订单级指标 × 品类继续 fail-closed `1002000014`，**不改规划器、不做隐式去重、不近似降级**。
3. **订单项金额不在首版**：`quantity × price` 需指标表达式能力或新增 `amount` 列 + 数据回填，二者均超出 W1 范围。登记为后续项（M7+），实现前另发 ADR；**禁止**在编译器里内联表达式绕过指标契约。
4. **test 集升 v4**（v3 归档）：
   - `t-agg-single-17` / `t-yoy-06` 去掉 `skipReason`，**转为预期拒绝正例**进入分母（判据 = `rejected` 且 `errorCode=1002000014`，runner 已支持）；
   - 新增 2 题订单项销量正例：`t-agg-single-17b`（「今年各商品品类的销量是多少」）与 `t-yoy-06b`（「今年各品类销量同比变化」），期望 `QUERY` / `YOY_MOM` + `metric.order_item_quantity` + `dim.product_category`；
   - 登记新 `contentHash`；test 集 v4 冻结后只允许升版。
5. **清单升 v17**：在 v16 基础上新增指标定义；**`scenario.sales` 的 scope 不扩**——`ontologyScope.excludedConcepts` 继续排除 `concept.product` / `concept.order_item`，`semanticScope.metrics` 不加入新指标；订单项销量**只在自由问数可用**。任何场景要支持订单项销量，须新场景资产或 scope 变更并另发 ADR（场景只收窄、不扩权）。对外宣示不得写「按品类的订单数 / GMV / 客单价」，可写「自由问数支持订单项销量」。
6. **发布流程**：v17 走 dry-run 预检 → 确认发布 → 激活，登记 `manifest_id + contentHash`；不得跳过预检或直接改库。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 方案 B（订单级去重后再分组） | 需证明「订单数按品类去重」可解释（一单多品类如何归属），语义争议大；且会改变订单数口径，风险高于新增订单项指标 |
| 首版新增 `order_item.amount` 列并回填 | 需 Query DS 迁移 + 历史数据回填 + 新指标，超出 W1 范围；且金额口径（是否含优惠/退款）未定 |
| 指标表达式（`quantity * price`） | 改动编译器与指标契约，扩大确定性边界风险；应作为独立能力评估，不在 E-5 顺带引入 |
| 维持 ADR-0016 现状（不做） | 品类维度继续「存在但不可用」，E-5 永久挂账；M7 决策 1 已定档实现 |

## 后果

- **正面**：自由问数可回答「各品类卖了多少件」；`dim.product_category` 不再悬空；订单数题继续以 fail-closed 验证安全边界。
- **负面**：订单项金额暂不可用；`scenario.sales` 内仍不可用（scope 收窄，符合「场景只收窄」）；需清单 v17 与 test 集 v4 两个升版；品类分析话术需区分「销量」与「订单数」。
- **不受影响**：订单级指标（不分组品类）、LOOKUP 按 `product_id` 查品类属性、跨域拒绝路径。
- **复核**：M7 E1 验收时核对 ADR + 清单 v17 + test 集 v4 + runner 证据；若后续实现金额，需新 ADR 并同步清单/test/能力声明。

## 回退方案

清单回滚到 v16（激活旧版本）、test 集回退 v3、指标定义移除；已发布的 v17 保留只追加历史，不原地改。回退不改变 ADR-0016 的 fail-closed 口径。
