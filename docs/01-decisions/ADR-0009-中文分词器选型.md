## 背景

技术选型 §11 第 3 项要求阶段零冻结中文分词器选型并核实许可。用途（技术选型 §4.5）：
应用侧分词写入 `asset_candidate.search_tsv`（tsvector 生成列 + GIN），词典与 Synonym 资产同源；
M1 已交付业务化 `aliases` 字段作为词表来源。分词器**实现归 M5**，本 ADR 只冻结选型与许可结论。

## 决策

1. **定案：IK Analyzer 方向**（Apache 2.0，可自由商用；Elasticsearch 生态长期维护）。
   - 理由一（许可清洁）：HanLP 本体代码为 Apache 2.0，但**内置语料/模型数据采用不可商用的自定义许可**（商用需购买授权）——对将被数十副本加载的检索组件，语料许可污染是结构性风险；
   - 理由二（够用）：本项目分词对象是**资产词表**（业务名 + 别名，数百条级别），不是开放语料——词典驱动的 IK 形态与「aliases 同源维护」架构天然匹配；检索主力是精确 + `pg_trgm`，分词只服务 search_tsv 生成；
   - 理由三（架构对齐）：应用侧分词 + 自定义词典可完全由 Synonym/aliases 资产生成，消除双真源。
2. **HanLP 登记为备选**：若 M5 配对评测（PoC #5）证明词典驱动召回率不达标（<95%），升级 HanLP 前必须完成其模型数据商用授权评估与采购决策——列为独立决策，不在本 ADR 预授权。
3. **实施约束**：分词器在应用侧调用（不装 PG 扩展，对齐技术选型「零第三方扩展」原则）；自定义词典由发布清单的 aliases 资产生成；实现与验收随 M5 检索瀑布（PoC #5 判据）。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| HanLP（词典+模型双形态） | 模型/语料数据不可商用，需采购授权；M5 前无法证明词典驱动不够用 |
| jieba（Python） | 技术选型锁定 Java 底座，跨语言桥接违反原则 |
| 不做分词，纯 pg_trgm + 字面匹配 | M1 机械闸门已证明字面匹配可行但召回有上限；M5 PoC #5 判据要求 ≥95%，需要分词支撑 |

## 影响

- M5 检索瀑布任务含 IK 集成（自定义词典从 aliases 资产生成）；
- PoC #5（≥300 条提及样本 Top-5 召回 ≥95%）以 IK 分词为被测对象；
- 版本事实台账补 IK Analyzer 许可条目（Apache 2.0，来源 wenerme/IKAnalyzer 维护版）。

## 回退方案

M5 PoC #5 召回率不达标时：先调 IK 词典与同义词资产；仍不达标 → 启动 HanLP 商用授权评估（独立决策）或评估阿里云 ES 内置 analysis-ik 的托管形态；「模糊候选进 DSL 次数为 0」与授权子图约束在任何分词器下不变。
