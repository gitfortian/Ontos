## 背景

M7 实施至 W5/T5.3（2026-11-11），E1、E2、E4（五类攻击面部分）、E5、E6、E7、E8 均已取得可复算证据；
**E3（LLM 路径评测 E-7）无法执行**，原因不是实现缺陷，而是**没有可用的模型服务**：

1. 仓库的模型接入只认 OpenAI 协议三件套（base-url / api-key / 模型名），当前环境未提供可用端点与凭据；
2. W2（T2.1–T2.4）与 W3/T3.2（LLM 新攻击面）在规格里显式依赖 T2.1「模型服务与版本锚定」，模型未锚定即无法开工；
3. 规格 §6 末尾已预设本情形的处置：「E3 若因模型服务不可用无法完成，必须发 ADR 登记『M7 有条件通过』并明确 M8 前补测触发点，**不得用降级路径结果替代**」。

T5.1 建立的**本地 OpenAI 协议桩**（`scripts/verify/mock-openai-model.mjs`）只用于验证「模型调用被正确追踪」与「并发下追踪不丢行」，它固定返回合法提案，**不具备评测意义**，不能替代 E-7。

## 决策

1. **M7 判为「有条件通过」**，条件项两项：

   | 编号 | 条件项 | 现状 | 证据 |
   |---|---|---|---|
   | **C-1** | E3 / E-7：test 集在 LLM 路径下全量 ×3、分层 + Wilson、`fallback_reason` 单列、意图一致率代理口径、与降级路径 McNemar / 配对 bootstrap、成本统计 | **未执行**（T2.1–T2.4 全部未开工） | [M7 验收报告 v1 §2](../06-verification/checklists/M7-验收报告-v1.md) |
   | **C-2** | E4 的「LLM 新面」与 T3.2：工具越权 / 上下文污染 / 输出解析 / fail-closed 四类攻击面探针 | **未执行**（依赖 T2.1） | 同上 |

2. **触发点与责任**：

   - **触发条件**：项目负责人提供可用的模型服务（base-url、api-key、模型名三件套）并确认调用预算；
   - **完成时限**：触发后 **5 个工作日内**完成 T2.1–T2.4 与 T3.2，并把《M7 验收报告》升 v2、本 ADR 状态改为「条件已解除」；
   - **硬门禁**：**M8 不得在 C-1/C-2 闭环前进入「发布/灰度」环节**；M8 的设计、部署脚本、网关与灾备等不依赖评测结论的工作可先行。

3. **禁止事项（防止「假闭环」）**：

   - 不得用确定性降级路径的评测结果替代 LLM 路径结论；
   - 不得引用本地协议桩的延迟、token、成功率作为 E-7 或成本证据（桩只证明链路连通与追踪完整）；
   - 不得在模型服务未锚定时「先跑一遍算通过」——E-7 要求记录实际模型名与运行参数，缺一项即无效运行。

4. **M7 其余判据的效力不受本 ADR 影响**：E1/E2/E4（五类）/E5/E6/E7/E8 的结论按各自证据独立成立，不因条件项存在而降级为「未验收」。

## 影响

- **正面**：阶段文档与台账可以如实结项，M8 的工程准备不被评测阻塞；条件项有明确触发条件、责任人与时限，不会变成口头欠账。
- **负面**：M7 不能宣称「全绿」；`E-7` 相关的三项指标（LLM 成功率、成本、意图一致率）在补测前**不可引用**。
- **对下游**：M8 上线清单（v1.4 §18）中的「评测达标」项必须引用 M7 报告 v2，不能引用 v1。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 用降级路径结果充当 E-7 | 违反规格 §6 与 ADR-0005；两者回答的是不同问题（降级路径测确定性检索，E-7 测模型编排），混口径即失真 |
| 用本地协议桩跑 test 集 | 桩固定输出，成功率必然接近 100%，是自证；且无法测成本与意图一致率 |
| 暂不结项，等模型服务到位再出报告 | 阶段文档长期悬空，M8 无法排期；且已完成的 E1/E2/E4/E5/E6/E7/E8 证据无法被正式引用 |
