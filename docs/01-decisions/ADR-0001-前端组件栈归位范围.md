## 背景

此前把「参考 yak-ops 前端工程规范」误执行为「连组件库一起搬迁」，`packages/ontos-ui` 整包复制了来源项目基于
`@base-ui/react` 的组件实现。用户澄清：**参考的只是工程规范（目录分层、service 三层、状态与请求原则、命名、
Lint/格式化、架构检查、测试方式），框架组件一律用技术选型 v1.1 附录 A 的选型**。

M0 规格 §8 评审结论把归位范围列为待决项（T5.1），本 ADR 冻结该范围。

## 决策

1. **共享组件层**：按附录 A 实现为 **shadcn/ui + Tailwind v4 + Radix**（copy-paste、源码自有），
   移除来源项目组件库及其 `@base-ui/react` 依赖；组件 API 由共享包的 `src/index.ts` 统一导出。
2. **包管理**：切换为 **pnpm workspaces**（附录 A 锁定），同步 `pnpm-workspace.yaml`、脚本命令、
   `ontos-ui/docs/tooling.md` 与 `scripts/verify-baseline.mjs`。
3. **AG-UI 接入时机**：**CopilotKit Headless 等 PoC #10 验收通过后再接入**。验收前保留当前可运行的
   SSE 实现；PoC #10 先用独立验证页验协议（T3.2），再在归位后的组件层上做界面复验（T3.5），
   由复验结论决定主路线或退路（`@ag-ui/client` + 自研渲染层）。
4. **附录 A 不修改**。用户最新决策与附录 A 选型一致，冲突来自实现偏离，不是文档错误。
5. **工程规范不变**：目录分层、`service/http` 三层、TanStack Query、Oxlint/Oxfmt、架构检查与设计 token
   约束全部保留；组件归位只替换「用什么组件」，不改「怎么写」。

## 依据

- 用户 2026-11-06 明确澄清「我只是让参考其前端代码规范，框架组件还是用我们的选型」；本次确认「第二个按照你推荐的吧」。
- 技术选型 v1.1 附录 A 冻结：shadcn/ui + Tailwind v4 + Radix、CopilotKit Headless、Vite + TypeScript + pnpm，
  纯静态产物由 Spring Boot 单体托管，不引入独立前端服务。
- PoC #10 是附录 A 主路线的硬判据，未通过前把 CopilotKit 引入产品主干会有返工风险。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 保留来源组件库，只改包名 | 违反用户澄清与附录 A，后续页面越写越难替换 |
| 立刻接入 CopilotKit Headless | #10 未验收，主路线未定；违反 M0 规格 T3.2/T3.5 的两步判据 |
| 保留 npm workspaces | 附录 A 锁定 pnpm；两套包管理会让 CI 与文档口径分裂 |
| 修订附录 A 迁就实现 | 附录 A 是冻结选型，冲突来自实现偏离而非文档 |

## 影响

- `ontos-ui/packages/ontos-ui` 组件实现重写；四个页面的组件引用需适配（保持 `app/<域>` → `service/<域>` → `service/http` 分层）。
- `ontos-ui/package.json`、`apps/web/package.json`、共享包 manifest、lockfile、CI/基线脚本命令同步。
- `ontos-ui/FRONTEND_RULES.md`、`docs/tooling.md`、`AGENTS.md` §6 去掉「临时状态」标注。
- 架构检查脚本需适配包名/路径映射，**不得删除或放宽约束**；变更须在本 ADR 记录。
- W5 完成后才能启动 T3.5（#10 界面复验）。

## 回退方案

若 shadcn/ui + Radix 组件层在归位中无法满足现有页面交互，按附录 A「基础组件层不变」的约束，
只调整组件实现与适配层，不回退到来源组件库；若 PoC #10 主路线不通过，按附录 A A.3 退到
`@ag-ui/client` + 自研渲染层。

## 后续动作

- T5.2 替换共享组件层；T5.3 迁移四页；T5.4 更新规范文件；T5.5 依 #10 结论接入。
- 每步完成后跑 `pnpm check`、`pnpm build` 与 `node scripts/verify-baseline.mjs`。
- 归位完成后在本 ADR 追加「已实施」记录；本 ADR 被取代时按文档规范标记，不删除、不复用编号。

- **T5.5 结论（2026-11-07，更正条目）：不接入 CopilotKit，走退路。**
  > 治理说明：上一行结论曾在 2026-11-07 被原地改写，为符合「冻结不可原地改」条款已恢复原文并以更正条目追加。

  CopilotKit 列为观察项，M1 复查是否有正式 non-runtime 接入方式。详见 [T5.5 报告](../06-verification/poc/T5.5-CopilotKit接入验证-v1.md)。
