# ADR-0006 · G2 有条件关闭与重开口径

> **上游依据**：[M0 实施规格 §6 G2](../03-plans/stages/M0/M0-工程基线与阶段零硬判据-实施规格-v1.md)、[PoC-03 · AgentScope 准入](../06-verification/poc/PoC-03-AgentScope准入.md)、[技术选型 v1.1 §7 #3](../02-solutions/architecture/智能问数系统技术选型方案-v1.1.md)、[M0 验收报告 v2](../06-verification/checklists/M0-验收报告-v2.md)

## 背景

实施规格 G2 的原始判据是二选一：「`#3` BETA 准入通过，**或**已完成 2.0.4 回退验证并记录差异」。
PoC-03 实测结果：四项判据里三项达标（artifact 坐标、Boot 4.0.1 兼容、破坏性 API 差异清单），
第四项「五类结构化终态 20 次会话重建 100%」未达标——协议层 100%、语义层 68.8%（11/16），
界面侧另跑 20 次全部一致。两批差异经逐条核对来自模型输出契约遵循度的批次波动，非框架能力缺陷。
2.0.4 回退验证从未执行（PoC-03 §7 仅确认回退目标保持 2.0.4 不变）。

即：G2 的两个原始分支都未满足，M0 无法按规格字面关闭 G2。负责人 2026-11-07 确认「有条件关闭」
（沿用 `#1`「限定范围通过」签字先例）。M0 深度审计（2026-11-07）指出该关闭存在两个缺口：
①闸门级决策无 ADR 记录（对比 `#1` 落入硬阻断结论签字段、`#7` 落入 ADR-0002）；②重开规则
「重跑探针未达 100% 则重开」在已实测的批次波动（同一 prompt 下 50%–81% 波动）下不可稳定判定，
单批 20 次重跑大概率偶发 100% 或偶发失败，形同虚设。本 ADR 修复这两个缺口。

## 决策

1. **G2 正式有条件关闭**：签字记录于本 ADR（取代验收报告 v1 头块中无决策载体的表述）。
   依据：三项判据达标 + 根因定位到模型契约遵循度 + 界面侧 20/20 一致 + 修复方案明确且登记 M1 首批。
2. **重开口径（可判定）**：M1 的服务端程序化校验 + 重试落地后，以 PoC-03 同款探针在**新代码**上执行：
   **连续 3 批 × 20 次会话（共 60 次，跨至少 2 个自然日执行以覆盖批次波动），每批语义一致率 100%**
   方维持关闭；**任一批 < 100% 即重开 G2**，并启动 2.0.4 回退评估（PoC-03 已产出破坏性差异清单，
   回退评估以该清单为输入）。判定层级以**协议层探针**（`run-poc03-terminal-states.mjs`）为准，
   界面层复验仅作佐证。
3. **M1 修复的验收归属**：重开判定由 M1 阶段负责执行并出具报告（落点 `06-verification/poc/`，
   命名沿用 PoC-03 升版）；未执行重开判定前，M1 不得把 G2 视为已通过。
4. **真实数据边界不受本 ADR 影响**：G2 的关闭不解除「真实敏感数据测试以 M4 复验登记为边界」的全局约束。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 按 G2 原分支执行 2.0.4 回退验证 | 工作量大且当前代码与 2.0.4 存在已确认 API 差异；在根因已定位为模型契约（非框架）时，回退不针对问题本体 |
| M0 内实现服务端校验 + 重试后硬关闭 | 该修复属 M1 的 AG-UI 适配层工作（M1 会重写该层），提前实现有返工风险，违反 M0 边界纪律 |
| 重开规则维持「重跑一次达 100% 即维持」 | 在已实测批次波动下单批判定不可稳定；审计明确指出该口径形同虚设 |
| G2 记为「未关闭」推迟到 M1 | M0 规格要求 G1–G8 全部关闭才退出；二选一分支均不可达时，规格外的第三状态必须有签字与决策载体，否则验收报告自相矛盾 |

## 影响

- 验收报告 v2 的 G2 行引用本 ADR；`M0-PoC总览` 与 roadmap 的 G2 表述随之对齐。
- M1 首批任务新增「#3 修复 + 按本 ADR 口径执行重开判定」；执行前 G2 维持「有条件关闭」状态。
- PoC-03 报告保持 FAIL 结论不动摇；本 ADR 只定义关闭状态与重开机制，不改变任何实测数据。

## 回退方案

若 M1 重开判定未达标（任一批 < 100%）：G2 重开，M1 编码不停止（G2 属准入闸门而非 M1 编码前置，
见实施规格 §8 评审记录），但 **2.0.4 回退评估必须在 G2 重开后 5 个工作日内启动**并出具结论；
评估结论为「必须回退」时，按 PoC-03 §7 的回退路径执行并重新验证事件协议。

## 后续动作

- M1 实施规格编写时，把「服务端校验 + 重试」与「按本 ADR 口径的重开判定」列为显式任务与退出条件。
- M0 验收报告 v2 §4 的遗留登记引用本 ADR，替代 v1 的自由文本表述。
