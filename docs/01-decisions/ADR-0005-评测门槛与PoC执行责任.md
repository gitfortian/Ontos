# ADR-0005 · 评测门槛与 PoC 执行责任

> **状态**：已冻结
> **版本**：v1
> **类型**：决策
> **负责人**：项目负责人（2026-11-07 确认按建议执行）
> **最后更新**：2026-11-07
> **适用范围**：M0 / W4 / T4.4；M0 起全部 PoC 的判据与门槛
> **上游依据**：[技术选型 v1.1 §7](../02-solutions/architecture/智能问数系统技术选型方案-v1.1.md)、[M0 实施规格 §6](../03-plans/stages/M0/M0-工程基线与阶段零硬判据-实施规格-v1.md)
> **修订记录**：2026-11-07 v1 首次冻结，确认门槛、责任与执行顺序，并记录已执行项的时序偏差

## 背景

判据要求「门槛在**看结果之前**冻结，之后不得因结果不理想而下调」。若等到十项 PoC 都跑完再冻，
等于用结果反推门槛，判据就失去意义。

本 ADR 的作用是**确认并锁定**：已执行项按 §7 原判据执行、未执行项按 §7 建议初值冻结、后续不得下调。

## 决策 1：门槛就是 §7 的建议初值，一字不改

**全部十项的门槛直接采用技术选型 §7 表格中的「建议初值」，不新增、不放松、不细化。**

本 ADR 不复制阈值（SSOT 在 §7），只做三件事：

1. 声明这组初值**即刻生效为正式门槛**；
2. 明确**不得因结果不理想而下调**；
3. 登记已执行项的时序情况（见决策 3）。

## 决策 2：变更规则

| 情形 | 是否允许调整 | 处理方式 |
|---|---|---|
| 结果不达标 | **不允许下调** | 记 FAIL，走 §7 的退路，或登记为阶段能力不足 |
| 环境不具备（如无 pgbouncer、无 3 副本） | 允许**标记未运行** | 拆到对应阶段补验，不折算为「部分通过」 |
| 判据表述与实测不符 | 允许**纠正表述** | 报告按实测写，ADR/升版记录，**不据此放宽通过标准** |
| 判据本身有歧义导致无法判定 | 允许**补充判定口径** | 必须在结果产出**前**补充，并说明为何原表述不可判定 |

第四行是本次实际遇到的：#3 的「终态重建成功率」同时含「协议能否承载」与「语义是否匹配」两层，
原表述无法区分。补充口径时**两层都报**，取更严的一层作为判据结论，不放宽。

## 决策 3：已执行项的时序登记（必须如实记录）

十项里 6 项已在 M0 期间执行。它们**不是**在看完结果后才定门槛的，但也**不是**严格按「先冻门槛再跑」的顺序：

| 项 | 执行时依据 | 门槛是否被调整过 |
|---|---|---|
| #1 RLS | §7 原判据 | 否（3 项未运行是环境所限，未记为通过） |
| #2 快照可复现 | §7 原判据 | 否 |
| #7 跨轮差分 | §7 原判据 | 否（现行初值 FAIL 后，是**修订规则**并另发 ADR-0002，不是下调门槛） |
| #3 AgentScope 准入 | §7 原判据 | 否（补充了「协议层/语义层」两层口径，见决策 2 第四行） |
| #4 编译器 SQL | §7 原判据 | 否（覆盖度不足记「部分通过」，未降低逐字比对要求） |
| #10 前端直连 | §7 原判据 | 否（补了「流式时序」这一**更严**的补充判据） |

**关键说明**：#7 是最容易被误读为「下调门槛」的一项。事实是——现行 §4.8 建议初值实测 FAIL 后，
**没有改判据的通过标准（泄露 0 / 误报 ≤2%），而是改规则实现方式**（精确差分即时转审批），
并走 ADR-0002 冻结。判据门槛从头到尾没动。

## 决策 4：责任人与执行顺序

### 责任人

| 角色 | 人 | 职责 |
|---|---|---|
| 判据与门槛冻结 | 项目负责人 | 本 ADR 签字 |
| PoC 执行 | 项目组 | 探针编写、执行、原始数据归档 |
| 结论审查 | 项目负责人 | 核对「实测 vs 报告结论」是否一致，签 PoC 报告 |

当前为单人项目，执行与审查同人，**这本身是风险**：自查容易放过「报告比实测乐观」的问题。
缓解措施：每份 PoC 报告必须附原始 JSON，且结论段落必须能逐条回溯到原始数据（本仓库已按此执行）。

### 执行顺序

§7 规定按阻断级别：`#1 → #2 → #7 → #3 → #4 → #8 → #10 → #5 → #9 → #6`。

实际执行：`#1 → #2 → #7 → #3 → #4 → #10`，**#10 提前、#8 跳过**：

| 偏离 | 理由 |
|---|---|
| #8 复合拆分跳过 | 依赖多意图独立编译，而编译器当前只支持单意图（PoC-04 实测 1/5 模式），先做等于测空气 |
| #10 提前到第 6 位 | 不依赖 #8；且它决定前端主路线（CopilotKit 是否成立），越晚出结论，前端返工面越大 |

**顺序偏离不改变判据**，只是排期调整；#8 仍在 M2 补齐编译器后执行。

## 依据

- §7 明确「建议初值须由项目负责人在查看正式结果前冻结」；本 ADR 是该冻结动作的落地记录。
- 已执行 6 项的判据文本从未改动，改动过的只有「判定口径的澄清」与「规则实现的修订」，二者都不降低通过标准。
- 单人项目缺少交叉复核，必须以「原始数据可回溯」替代。

## 备选方案

| 备选 | 为何未选 |
|---|---|
| 等十项都跑完再冻门槛 | 等于用结果反推门槛，判据失去约束力 |
| 对已执行项重新按新门槛复测 | 判据未变，复测只增加噪音；真正需要复测的是 #3（口径已澄清），已重跑 6 轮 |
| 引入外部评审替代自查 | 当前无此资源；以「原始 JSON + 逐条回溯」替代，M1 起可考虑引入 |

## 影响

- 后续 #5 / #8 / #9 / #6 执行时，**必须先用 §7 原判据写探针，再跑**，不允许「先跑看数、再定判据」。
- 任何门槛调整只能发新 ADR 取代本 ADR，并在进度中记录触发原因。
- PoC 报告模板需固定「原始输出路径」一节（现有报告已满足）。

## 回退方案

无。门槛只可维持或收紧，不可放宽。若某条判据被证明**不可判定**（而非不达标），
按决策 2 第四行补充口径并说明，仍需保留原判据的严格程度。

## 后续动作

- `#5` / `#8` / `#9` / `#6` 执行前，先提交探针与样本，再跑数据。
- M0 收口时（G8），逐条核对十项结论与原始数据是否一致。
