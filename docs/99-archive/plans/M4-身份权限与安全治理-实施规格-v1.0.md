## 1. 目标与非目标

**目标**：把「应用层策略 + DB 层 RLS」做成双边界，替换当前 fail-closed 占位实现（`PolicyService.check` 现在除 dev-allow-all 外无条件拒绝）。

**非目标**：
- Scenario scope 裁剪（M6）；M4 的授权以「用户授权全域」为唯一 scope。
- 编排层候选集外 ID 检查的**运行时**联动（归 M5——M4 落地检查点框架与 DSL/API 层身份不可覆盖，编排接入在 M5 规格中引用）。
- VQR 权限重编译（M6/VQR 范畴；M4 只保证策略版本进缓存键与审计）。
- RLS 规则变更（PG 侧 RLS 在 M1 已验收，M4 只做回归与「策略版本一致性」核验，不改 RLS 定义）。

## 2. 现状基线

- `V1` 已有 `approval_request`（含 EXPIRED 态 CHECK）、`sensitive_query_event`（缺列，见 §3.1）、`domain_combination_policy`、`audit_log`（含 parent/sub_intent）。
- `ApprovalService` 已有 page / decide（决策人取上下文），**无创建入口、无超时失效、无查询联动**。
- `PolicyService.check()` 为 fail-closed 占位（无条件 FORBIDDEN）；`dev-allow-all` 开关存在。
- `DslValidator` 注释明确：「完整累计检测（sensitive_query_event 落库 + 窗口聚合）归 M4」。
- 技术选型 §4.8 已冻结差分框架：**两层判定**（session 级跨会话清空 + user+tenant 级滑动窗口不清空，OR 关系）、
  **分层阈值初值**（L1 PII 24h/T=8、L2 存在性 24h/T=4、L3 label 7d/T=3）、
  **禁止进程内计数**（事务内落 PG + 窗口聚合 SQL 判定）。
- ADR-0002 冻结精确差分规则：精确差分（同指标、同粒度、过滤仅维度值不同的相邻查询）**即时转审批**。

## 3. 设计

### 3.1 策略快照（§10.1 四层中的语义层落库）

```
policy_snapshot:  snapshot_id + tenant_id + policy_version + payload(JSONB) + created_at/created_by
                  不可变（与 published_snapshot 同构）；payload 含：
                  roles:        [{role_id, name, description}]
                  assignments:  [{user_id, role_id}]
                  assets:       [{asset_type(metric|dimension|property|entity|rule), asset_id,
                                  effect(allow|deny), sensitivity_class(public|internal|pii|existence|label)}]
                  domainCombination: 直接沿用 domain_combination_policy 表（保持 V1 结构）
```

- `RequestContext` 携带的策略版本与当前生效快照不一致时拒绝（fail-closed，防降权后用旧权限）。
- 缓存：`PolicySnapshotService` 按 tenant 缓存已解析授权集（`@Cacheable` 语义手写 Map + 版本键），快照激活时失效。
- **`dev-allow-all` 生产禁用**：开关仅允许在 `local`/`dev` profile 生效；`prod` profile 下为 true 直接启动失败。
- 授权判定点：指标（聚合模式）、实体（lookup）、属性（投影/过滤/时间维度）、Rule（布尔判定）；**未登记即拒绝**（allowlist）。
- 敏感分级消费：`pii` → 脱敏返回（M2 掩码已有，补策略开关）；`existence` → `ATTRIBUTE_NOT_AVAILABLE` 统一文案；
  `label` → 拒绝个体判定（`100100000x` 新码），聚合分布放行或走审批。

### 3.2 跨轮敏感累计（§4.8 / ADR-0002，PoC #7）

- `V9` 迁移：`sensitive_query_event` 扩列至技术选型 §4.8 全量
  （request_id / sensitive_key / sensitivity_class / scope_hash / filters_hash / result_cardinality / pattern_tag / reason_code / context_delta）。
- 写入点：`QueryServiceImpl` 执行成功后**同事务**写事件（禁止进程内计数）；只对 L1/L2/L3 分级资产写。
- 两层判定（§4.8 框架）：
  - **session 级**：同 session 同 sensitive_key 计数 ≥ T → 触发；
  - **user+tenant 级**：24h/7d 滑动窗口 SQL 聚合 ≥ T → 触发（跨会话规避）；
  - OR 关系，取动作档位较高者；交互反馈只读 session 级计数。
- 触发动作：自动创建 `approval_request`（kind=SENSITIVE_SEQUENCE，payload 带触发上下文）+ 返回 `SENSITIVE_QUERY_SEQUENCE`；
  **精确差分**（ADR-0002：同指标同粒度、filters 仅维度值不同）不计数直接转审批。
- 跨会话规避检测：user+tenant 级窗口天然覆盖（每轮新 session 仍累计）。

### 3.3 审批闭环

- 创建入口：`ApprovalService.create`（内部调用，来自敏感累计 / label 判定 / 域组合需审批三类触发）。
- **超时失效**：查询时惰性过期（读到 PENDING 且超 `ontos.approval.ttl` 即置 EXPIRED）+ 启动扫描兜底；TTL 默认 PT15M。
- **审批通过放行**：放行令牌（approval_id + 目标指纹）绑定一次执行；`QueryService` 校验令牌有效后放行该次查询，
  令牌消费后不可复用（单次有效，防审批复用放大权限）；审计记录 approval_id。
- HITL 回传：AG-UI `interrupt` 事件下发审批入口（最小通道验证，完整对话内联审批归 M5 编排接入）。
- 决策人：沿用 `decidedBy` 取认证上下文；补校验「决策人 ≠ 申请人」（自审批禁止）。

### 3.4 提示注入检查点（框架先行，编排接入归 M5）

- 身份声明不可覆盖：身份只来自认证上下文（架构已保证）；M4 补 **API 层回归**——请求头身份与任何 body 字段不一致时以头为准且审计（现在没有 body 身份字段，回归用例证明不可注入）。
- 候选集外 ID / PROMPT_INJECTION_SUSPECTED：定义检查点接口与审计 action（`INJECTION_SUSPECTED`），M5 编排调用。
- 前端事件日志脱敏：`redact.ts` 已有；补 `RUN_STARTED.input` 脱敏的服务端验证用例（PoC #10 判据的前置部分）。

## 7. 风险与回退

| 风险 | 回退 |
|---|---|
| 策略误配导致全站拒绝（fail-closed 的代价） | 种子快照与首发资产清单逐项核对 + 只读校验命令；错误码区分「未授权 / 未登记」 |
| 窗口聚合 SQL 性能（每请求 2 次窗口查询） | 只对 L1/L2/L3 资产执行；索引按 (tenant, user, occurred_at)；高频场景允许配置关闭 user 级窗口（登记偏离） |
| 审批令牌被复用放大权限 | 令牌单次消费 + 目标指纹绑定 + 审计 |
| dev-allow-all 误入生产 | profile 守卫启动失败（fail-closed） |
| 敏感事件表膨胀 | 窗口外数据归档清理策略归 M8 |

## 8. 设计决策（2026-11-09 已确认）

1. **策略快照形态**：建议**不可变 JSONB 快照**（与 published_snapshot 同构：`policy_version` 锚定、
   整体激活/回滚、缓存键天然绑定版本）；备选是关系表（逐行授权，可增量改但版本一致性难保证）。
   种子角色建议 2 个：`role.analyst`（首发资产全量只读，email/手机号脱敏，label 拒绝个体）、
   `role.auditor`（仅审计查询）。
2. **敏感事件写入点**：建议**执行成功后同事务写入**（§4.8 「每请求一行」）——被拒绝的请求不计数
   （拒绝本身已有审计，且 fail-closed 下计数会放大误伤）；备选是「尝试即计数」（更严但会把正常被拒请求算进逼近序列）。
3. **HITL 回传边界**：建议 M4 只做 **AG-UI interrupt 事件的最小通道验证**（审批入口事件下发 + REST 决策回传），
   完整对话内联审批（在对话流里等待决策再继续 run）归 M5 编排接入；备选是 M4 直接做全内联（工作量与 BETA 协议风险前置）。

> **确认结论（2026-11-09 负责人）**：三项均按建议定档——不可变 JSONB 快照（含 2 个种子角色）、
> 敏感事件执行成功后同事务写入、HITL 最小通道（内联归 M5）。本规格据此冻结为 v1.0，W1 待启动。
