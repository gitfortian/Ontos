## 1. 目标与非目标

**目标**：把「调试工作台」变成业务用户可直接使用的智能问数产品入口——以对话为主交互，澄清 / 审批 / 结果 / 历史全部产品化；治理页面原样收进后台分组，不新增管理功能。

**非目标**：移动 App、国际化、会话协作分享、消息编辑撤回、可视化配置器、管理面功能增强、SSO 对接（列 M8）、CSV 导出（R1 F-8 砍除，随 M8 定档）。

## 4. 通道架构（R1 重写：run 事件流 = 唯一事实源）

### 4.1 Session–Run–Turn 三层模型（F-1）

| 概念 | 定义 | 来源 |
|---|---|---|
| **Session（会话）** | 一次产品对话的容器；**前端在首问时生成并全程复用**（F-5：现 ChatPanel 每轮换 session 导致指代消解 / 上下文继承 / 场景态全部失效——产品级缺陷） | 前端 `crypto.randomUUID()`，形如 `web-<uuid>` |
| **Run（轮）** | 一次编排执行（首问 / 澄清回传 / 审批续跑各产生新 run） | 服务端 `POST /ask/runs` 响应 `runId`（**后端需统一回显**，F-4） |
| **Turn（轮内回合）** | run 内的单次交互回合（多轮对话题内用户多句话） | run 事件流的 TURN 边界（spike 固化） |

UI 会话流 = **按 session 聚合、按 run 分段**：每个 run 的事件段自成一个「执行段」，段与段之间以用户消息 / 澄清回传衔接。

### 4.2 事件事实源

**Run 事件流是唯一事实源**（M5 R4/R5 幂等重放已落地）：

1. **首问**：`POST /ask/runs`（utterance）拿 `runId` → 订阅该 run 的事件（AG-UI SSE 若 D1=A；否则 events 轮询 / SSE 化重放，传输细节由 D1 定，事实模型不变）；
2. **澄清回传 / 审批续跑**：`POST /ask/runs`（utterance + `clarificationChoice` / 审批字段）拿新 `runId` → 同样订阅事件；
3. **断线续播**：`GET /ask/run/{runId}/events?afterSeq=`（后端幂等重放，不重复触发审批 / 查询）；
4. UI 状态机只消费**一种事件模型**（run 事件），SSE 与重放仅是传输差异——F-2 修复。

### 4.3 后端配套（W-B，均为小任务）

| 任务 | 内容 | 来源 |
|---|---|---|
| W-B0 | `POST /ask/runs` 响应统一回显 `runId`（现状仅 waiting 态含） | F-4 |
| W-B1 | `GET /api/v1/ask/sessions`：按用户聚合会话（首问截断标题 / 最近时间 / 轮数）+ 会话→run 列表 | D4=a |
| W-B2 | `POST /api/v1/auth/login`：签发 M4 认证上下文 token（user / tenant / roles）；401 语义对齐 | D3=a |

| W-B4 | 结果 meta 增列类型（从词典推导 valueType：date / text / number） | F-7 |

## 5. 事件 × UI 映射

| 事件 / 载荷 | UI 呈现 | 约束 |
|---|---|---|
| `RUN_STARTED` | 会话轮开始（用户消息气泡已在位） | `input` 字段前端不展示、不上报（A.4） |
| `TEXT_MESSAGE_START/CONTENT/END` | 助手消息流式渲染 | 增量拼接 |
| `TOOL_CALL_START/ARGS/RESULT` | 执行步骤指示器（「正在执行查询…」摘要） | 参数与 SQL 永不出现在产品 UI |
| `CUSTOM` / `RUN_FINISHED`（终态载荷） | 终态卡渲染（§6.1） | **载荷确切位置与 schema 由 W0 spike 固化**（F-6） |
| HITL interrupt | 审批内联卡 | 置顶 + 输入禁用 |
| `state` | 会话态徽标 | M5 三态 |
| 终态 `query` | 结果表 + 元信息条（指标 / 口径 / 时间窗 / 行数 / 列类型）+ 图表 | `degraded=true` 显示「结果来自确定性检索（未走大模型）」 |
| 终态 `composite` | 子结果分组卡 | `subResults` 契约由 W0 固化（F-6） |
| 终态 `clarification` | 澄清四要素卡 | 回传协议见 §6.1 |
| 终态 `discovery` | 能力清单卡（三组，可点选发起） | 空数组给空态 |
| 终态 `out_of_capability` | 拒答文案卡（copy_template）+「查看可查资产」入口 | 不暴露内部码 |
| 服务端拒绝（业务码 ≠0） | 错误卡（中文人话）+ 重试 | 与网络错误分开呈现 |

## 6. 页面组件分解

### 6.1 对话主页

- `ConversationStore`：**每会话固定 session_id**（F-5）；状态机 = `idle → composing → running → (waiting_approval | clarifying) → finished | error`；run 进行中输入禁用（M5 R3 会话锁）；
- `ConversationStream`：按 run 分段的消息列表，长会话虚拟滚动；
- `Composer`：多行输入、Enter 发送 / Shift+Enter 换行、停止跟随（仅断开本地订阅，服务端 run 不取消——后端无取消端点，登记 Backlog）；
- `TerminalCard` 五类（§5）；
- `ClarificationCard`：回传协议 v1 = 点选传 assetId、默认建议传 `__default__`、跳过传 `__skip__`（W-B3 核对）；自定义输入仅在候选为空时出现；
- `ApprovalCard`：批准 / 拒绝 / 备注；
- `ResultTable`：500 行上限内前端分页（50 / 页）+ 列排序；**无 CSV 导出**（F-8）；
- `ResultChart`（D5=a）：**保守映射**——仅当结果 meta 列类型可用（W-B4）且维度恰 1 个 → 柱；含时间列 → 线；0 维单值 → 大数字卡；其余只给表。零基线、单位与口径标注、行数 < 3 不画图；
- `SessionStateBadge` / `EmptyState` / `ErrorCard` + `RetryButton`。

### 6.2 会话历史（D4=a）

- `SessionList`（W-B1）；`SessionReplay` 只读（复用对话流渲染器，复用幂等事件重放）。

### 6.3 登录（D3=a）

- `LoginPage` + 登录态解析 roles → 导航显隐（F-9）；401 统一跳转。

### 6.4 开发者视图（D8=a）

- 折叠抽屉（dev 角色）；状态行展示**候选域（full/retrieval）与词表规模、对账口径**（F-13）；事件日志 / DSL / 计划回放沿用现组件。

## 7. 非功能标准

- **性能预算**：首字 ≤ 2s；500 行表格首渲染 ≤ 500ms；TTI ≤ 3s（Playwright trace 测量，W9）；
- **无障碍**：全键盘可达、焦点顺序、对比度 AA；
- **安全**：D7 缓存策略；前端输入不可信（服务端唯一裁决）；重连幂等；
- **兼容**：Chrome / Edge 最新两个大版本；两档断点（D6=a）；
- **深色模式**：token 具备，首版浅色，深色 Backlog。

## 附录 A：E1 十类代表性问法

1. 单指标聚合：「上个月各地区的成交金额」→ query 结果表 + 柱图；
2. 多轮指代：同会话追问「那华南呢」→ 上下文继承（metric / time）；
3. 澄清点选：泛化问法 → 澄清卡 → 点选候选 → query；
4. 澄清跳过：默认建议 → 跳过降级 → 按 degraded 呈现；
5. 审批批准：敏感序列 → WAITING_APPROVAL → 内联批准 → 结果；
6. 审批拒绝：同上拒绝 → 拒绝文案终态；
7. 能力边界：清单外诉求 → out_of_capability 文案卡；
8. discovery：「我能查什么」→ 能力清单卡；
9. 复合意图：双意图一句话 → composite 分组卡；
10. 失败重试：断网触发错误卡 → 重试成功。
