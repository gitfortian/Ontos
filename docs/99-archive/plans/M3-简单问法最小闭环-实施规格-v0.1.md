## 3. 设计

### 3.1 数据模型 / Schema

**口径变体（`SemanticManifest.Metric.caliberVariants`）**：

```json
{
  "variantId": "metric.paid_gmv.ex_refund",
  "alias": ["去掉退款的成交额", "GMV 去退款版"],
  "condition": {"fieldId": "dim.refund_status", "operator": "EQ", "values": ["NONE"]},
  "version": "1.0.0"
}
```

- `condition` 复用现有 `QueryDsl.Filter` 结构（fieldId / operator / values），字段必须属于该指标同表且在该指标 `allowedDimensions` 内；
- 变体不覆盖指标口径的聚合与列，只追加一个确定性过滤条件；
- 变体 ID 进 DSL 与审计；`variantHint` 仍只作检索提示，不参与编译（M2 决策 4 不变）。

**文案模板（`ManifestPayload.CopyTemplate` 扩展）**：

```json
{
  "templateId": "template.reason.CALIBER_AMBIGUOUS",
  "reasonCode": "CALIBER_AMBIGUOUS",
  "locale": "zh-CN",
  "text": "这个指标有多个口径：{variant_aliases}。请选择其中一个。",
  "allowedPlaceholders": ["variant_aliases"],
  "version": "1.0.0"
}
```

- `reasonCode` 必填且 `(reasonCode, locale)` 唯一；
- `allowedPlaceholders` 白名单之外的 `{x}` 一律发布期拒绝；
- 占位符名不得是 `asset_names` / `physical_tables` / `sql` / `field_names`（v1.4 §5.12 禁止项）。

### 3.2 接口契约

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/query/skills` | 列出已注册能力与槽位 schema（只读） |
| POST | `/api/v1/query/skills/entity_lookup` | 能力调用：槽位 → DSL → 复用 `QueryService.execute`，返回 `lookupRows` |
| GET | `/api/v1/copy-templates/{reasonCode}` | 按原因码取渲染文案；未知原因码返回通用兜底（仍走模板，不拼字符串） |

- 能力调用沿用 `X-Request-Id` 幂等与审计；`action` 记 `SKILL_EXECUTE`，`metric_id` 为空、实体记入 `dsl_json`；
- 文案端点只返回 `{templateId, locale, text, version}`，不在错误响应里内联文案（错误契约保持稳定）。

### 3.3 关键流程

**能力调用**：`skillId + slots` → `SkillRegistry` 校验槽位（必填 / 未知槽位拒绝）→ 组装 `QueryDsl`
（只引用资产 ID）→ `QueryService.execute` → 去掉 `__identity` → 返回行 + `lookupRows`。
槽位里不允许出现物理表名 / SQL / 任意表达式。

**口径变体**：指标存在 `caliberVariants` 且 DSL 未给 `caliberVariantId` → `CALIBER_AMBIGUOUS`
（携带候选 `variantId + alias`，不猜）；给了但不属于该指标 → `DSL_INVALID`；给对了 → 编译期把
`condition` 追加到 WHERE（与 filters 同等地位，不引入 Join）。

**文案渲染**：`reasonCode` → 取 `zh-CN` 模板（缺省回退到同原因码任意 locale）→ 按
`allowedPlaceholders` 替换 → 任何未声明占位符 / 越界值 → 渲染失败并回退到通用文案（禁止把原始模板
或资产名透给用户）。

## 7. 风险与回退

| 风险 | 回退 |
|---|---|
| 变体把简单问法拖回聚合链路 | 变体只允许同表条件、不引入 Join；跨表变体直接拒绝并登记 M6 |
| 新模块膨胀 | 能力注册先放 `ontos-module-query` 的 `core/skill` 包；M5 需要会话编排时再抽模块 |
| 清单 v8 破坏 M2 Golden | 严格超集 + 发布前 dry-run + Golden 全量复跑（27/0 必须保持） |
| 文案模板与错误码漂移 | 单测覆盖 M3 涉及的原因码；缺模板走通用兜底并记 WARN |
| 前端回放依赖响应头 | `service/http` 只做「暴露 request-id」的最小改动，不改变错误契约 |

## 8. 设计决策（待负责人确认）

1. **能力注册落点**：建议先在 `ontos-module-query` 内新增 `core/skill` 包（`SkillRegistry` + `skill.entity_lookup`），
   **不新建 `ontos-module-agent`**。理由：M3 只有 1 个能力，新模块会引入空壳与模块依赖方向风险；
   M5 需要会话编排时再抽模块，迁移成本低于提前拆分的维护成本。
2. **口径变体承载**：建议**新增独立指标 `metric.paid_gmv`**（含 2 个变体），不给现有 `metric.gmv` 加变体。
   理由：给 gmv 加变体会让所有既有查询因缺 `caliberVariantId` 被拒（`CALIBER_AMBIGUOUS`），
   直接破坏 M2 Golden 与既有调用方；新增指标是 v8 严格超集，风险最低。
3. **文案模板响应形态**：建议**独立端点按原因码取**，不在错误响应里内联 `copy`。
   理由：错误契约保持稳定（`code/msg/data`），文案版本可独立升级；前端已有 `failureMessage` 收敛层。

> 上述三项确认后本规格升 v1.0 冻结，随后启动 W1。
