## 结论

**三条触发条件当前为 2/3，Scenario Entry Router 不接入瀑布。** 已发布的 v13 清单只承载 Scenario 元数据
（`scenario.sales`），运行时不做场景路由、不做 scope 裁剪——这正是 ADR-0004 §2.1 要求的「只发布元数据」状态。
T2.4 交付 scope 裁剪后，本记录升 v2 复核三条，全满足才允许 T2.4 把 Router 接入瀑布（授权裁剪后、L1 前）。

## 条件核对

### 条件 ①：编译器覆盖首发需要的分析模式，且编译层 fail-closed —— **满足**

| 模式 | 状态 | 证据 |
|---|---|---|
| QUERY / YOY_MOM / FUNNEL / LOOKUP / LOOKUP_BATCH | 已实现 | M2/M3 验收；M2 五模式 Golden **27/0**（v12→v13 清单下不回退） |
| RETENTION / ATTRIBUTION | 已实现 | M6/W1/T1.3–T1.4；M6 Golden **23/0**（留存 10 + 归因 8 + 漏斗 5）；真库执行验证 |
| DISCOVERY | 显式不实现 | `analysis-mode · discovery 边界声明 v1`：不进 DSL，`validateMode`/编译器均抛 1002000006，§9.2 由 M5 终态三键载荷承载 |
| 未实现模式的兜底 | fail-closed | `validateMode` 白名单外一律 `ANALYSIS_MODE_NOT_IMPLEMENTED`（PoC-04 修复口径）；编译器纵深防御同码 |

### 条件 ②：关系路径规划可用 —— **满足**

- M2/T3.1 交付 `JoinPathResolver`：跨表字段先解析 UNIQUE 路径，歧义/不可达/粒度扩散 fail-closed
  （`1002000014` 粒度扩散闸门，见 [ADR-0016](../../01-decisions/ADR-0016-品类维度与订单事实指标的粒度边界.md)）；
- 证据：M2 验收报告 E 判据、PoC-01 RLS 探针、` OntologyPathPlannerTest`（10 例）。

### 条件 ③：scope 裁剪在授权链路生效 —— **未满足（T2.4 交付物）**

- 现状：授权裁剪（M4 策略快照）已生效，但 `authorizedAssetIds ∩ semantic_scope ∩ ontology_scope` 的
  Scenario scope 裁剪尚未接入瀑布；
- T2.3 已交付的**前置件**：`ScenarioRouter` 确定性决策（五态 + entry_mode 三值语义 + 裁决顺序按
  [ADR-0017 D1](../../01-decisions/ADR-0017-M6外部评审裁决.md)）、`ScenarioRouteState` 三态封闭迁移表
  （25 例单测锁定）、pending_confirm 复用 M5 澄清回传校验通道（伪造确认被拒）；
- T2.4 交付后重核：候选集 = `authorizedAssetIds ∩ semantic_scope ∩ ontology_scope`，模式候选 ∩
  `allowed_analysis_modes`，**scope 只能收窄不能扩大授权**；T5.2 对抗探针覆盖 scope 越界 / scenarioId 直传。

## 启用前的保护措施（已生效）

1. **路由代码与瀑布隔离**：`ScenarioRouter` / `ScenarioSessionService` 是纯决策与状态机组件，
   没有任何瀑布接线点；`ArchitectureTest` 保证运行面不依赖 catalog；
2. **运行时读不到未路由的场景行为**：v13 清单虽含 scenario 元数据，但瀑布不消费 scenarios 段
   （T2.4 前无任何读取点）；
3. **pending_confirm 无法被伪造激活**：确认必须命中 M5 候选集合（原子 UPDATE），而候选集合只能由
   路由决策写入——路由未启用时不存在任何写入路径。
