## 2. 分项结论

### 2.1 `#1` RLS 最终边界 —— 有条件通过（系统级）

- 核心隔离判据全部通过：5 组用例 × 100 次 = 500 次检查，越权成功 **0**；`FORCE RLS` 生效；未设 GUC 时 0 行；事务级 GUC 随连接复用不串号；应用链路 `/query/execute` 只返回本租户 2 行。
- 未运行 3 项：RLS 谓词索引命中（3 行小表走顺序扫描，无统计意义）、策略版本入审计（属 M4 产品能力）、pgbouncer `transaction` 池行为（本地无 pgbouncer，以同一物理连接复用模拟）。
- 部分覆盖 2 项：`SET LOCAL` / `security_barrier` 仅验证 `set_config(..., true)` 事务级语义。
- **判定**：不阻断 M0（未运行项均为环境或阶段能力所致），但**不视为 G1 完全关闭**，须在 M4 与具备连接池的环境补验并另发版本。

### 2.2 `#2` 发布快照可复现 —— 通过（系统级）

- 真实 jar 启动 3 个独立进程（含 **2 次重启**），每次编译 100 次，共 300 次。
- 逐字一致率 **100.00%（300/300）**，跨进程摘要种类 = 1；`content_hash` 锚点稳定；SQL 全参数化，绑定值单独返回。
- 排除了两个非产物字段的口径歧义：`X-Request-Id`（每请求随机）与 `CompiledQuery.compiledAt`（编译时刻），二者不进入产物、也不由响应 VO 暴露。
- **判定**：系统级关闭，M0 后续不再重复验证。

### 2.3 `#7` 跨轮差分与存在性保护 —— 有条件通过（探针级）

- 现行 §4.8 建议初值（T(L1)=8）**不成立**：精确差分两轮即可反推个体值（20 行 − 19 行 = 那 1 个 VIP 的 salary），4 类攻击实测 **50 次泄露**，判据要求 0 → FAIL。
- 规格 §7 给出的退路「阈值下调」单独使用**不可行**：T(L1) 降到 4 能堵住泄露，但正常用户第 4 次同类查询即被转审批，误报率 **25%**，撞破 ≤2% 判据。
- 退路 B（T 不变，精确差分命中即转审批）实测 **PASS**：泄露 0、跨会话拦截 100%、原因码命中 100%、误报 0%、对外文案仅 1 种。
- 另发现三处规则歧义（差分对的包含关系、收窄的严格下降、L1 个体值审批），按字面最宽解释会必然撞破误报率判据。
- **判定**：签字采纳规则修订后按 PASS 计入 G1；**签字前按 FAIL 处理**，不得进入真实敏感数据测试。
- 按 M0 规格 §8 R2，本项为**探针级**，M4 须做集成复验（脱敏渲染、多副本共享计数、并发顺序），已登记于 §5。

## 3. 闸门判定（T2.5）

**结论：G1 未关闭，闸门不放行。**

| 范围 | 判定 | 依据 |
|---|---|---|
| 真实敏感数据测试 | **禁止** | G1 未关闭（§6 末句） |
| M1 编码 | **不启动** | §6「未全部满足 G1–G8，不进入真实数据测试、不启动 M1 编码」 |
| W2 收尾 / W3 准入 / W4 决策 | **允许继续** | 不依赖真实敏感数据；#3/#10 为独立判据 |
| W6 文档收口 | **允许继续** | 只做索引与验收报告 |

解除 G1 需要同时满足两条：

1. **#7 规则修订签字**（阻断项，见 §4 决策 1）；
2. **#1 未运行项补齐**，或由负责人明确以「限定范围通过」接受并登记 M4 复验（阻断项，见 §4 决策 2）。

> 本条为**停止记录**，不是放行记录。按 M0 规格 §7 风险表，硬阻断不通过时不得用「能启动」替代闸门判定。
