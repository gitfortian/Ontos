## 1. 目的与双层原则

本体的内部模型沿用 v1.4 §5.3 的标准术语（class / property / relation / cardinality / mapping）——
这些字面进入冻结文档、DSL、清单 Schema 与审计记录，**不可更改**（更改即破坏契约与可追溯性）。

在此之上，**一切面向人的表述使用业务语言**：资产的业务名、一句话说明、常见叫法、管理界面导航与文案、
给非工程读者的文档。原则一句话：

> **系统内部说标准话，对人只说人话；且"人话"本身是资产——它就是检索词库与澄清候选的来源。**

依据：零号冒烟集与 PoC #5 样本集实证，用户的真实提问是「卖了多少 / 成交额 / GMV」这类业务叫法，
而不是 `metric.gmv`。M1 建模时写的每一句业务表述，都会成为 M5 召回与 M6 澄清的原材料。

## 2. 术语映射表（对外统一用右列）

| 内部标准术语（Schema/代码/审计保留） | 业务叫法（界面/文档/资产描述用） | 示例 |
|---|---|---|
| Ontology Class | **业务对象** | 客户、订单、商品 |
| Ontology Property | **信息项** | 客户的邮箱、订单的下单时间 |
| Ontology Relation | **业务关联** | 客户「下了」订单 |
| Cardinality 1:1 / 1:N / N:1 / N:M | **数量关系**（自然语言，见 §3.3） | 「一个客户可以下多个订单」 |
| Mapping | **数据来源** | 客户存在 `customer` 表 |
| Metric | **指标** | 成交金额（GMV） |
| Dimension | **分析维度** | 按大区、按渠道 |
| Event | **业务事件** | 下单、退款 |
| Enum | **取值范围** | 订单状态：待付款/已付款/已取消 |
| Rule | **判定标准** | 高价值客户 = 近一年消费满 5 万 |
| Synonym | **常见叫法** | GMV、成交额、卖了多少钱 |
| Constraint | **业务限制** | 订单必须属于一个客户 |
| Model | **数据表** | `fact_order` |
| Scenario | **业务场景** | 销售日报 |

## 3. 资产业务字段规范（可验证契约）

### 3.1 必填业务字段

每条资产（业务对象/信息项/业务关联/指标/分析维度/业务事件/判定标准）必须包含：

| 字段 | 要求 | 用途 |
|---|---|---|
| `name` | 业务名，中文，≤ 8 字为宜 | 界面显示、澄清候选文案 |
| `summary` | 一句话说明，用业务语言写，不出现 §2 左列术语 | 界面详情、discovery 候选 |
| `aliases` | 常见叫法数组（同义词/口语/缩写），≥ 1 条 | **检索词库**（M5 召回、#5 样本集对齐） |

### 3.2 写作验收（外行可读）

- 资产描述不得出现 §2 左列术语与物理表名/列名（后者只允许出现在 mapping 字段）；
- M1 首发（T2.3）的验收含「外行可读检查」：负责人以非工程读者身份通读，读不懂即改；
- 敏感标记的展示统一为「**敏感（可查不可看值）**」与「**判定结果（依策略展示）**」，不直接暴露 `PII` / `label` 字面。

### 3.3 数量关系的自然语言映射

| cardinality | 展示文案 |
|---|---|
| 1:1 | 「对应一个」 |
| 1:N | 「可以有多个」 |
| N:1 | 「属于一个」 |
| N:M | 「可以互相关联多个」 |

### 3.4 关系动词也是资产

业务关联的正向名与逆向名（如 `placesOrder` → 正向「下了」、逆向「被…下单」）是检索与澄清的词汇：
M1 建模时每个关系必须写业务动词短语，动词的常见变体并入该关系的 `aliases`（如「下了/购买/产生」）。

## 4. 展示层规范（管理界面）

1. 导航、页签、卡片标题、空态与错误文案一律使用 §2 右列叫法；标准术语只出现在代码、Schema、审计与面向工程读者的文档；
2. 关系可视化渲染为「对象A —动词→ 对象B（数量关系文案）」；
3. 界面不出现 `class_id` / `property_id` 等内部 ID 作为可见文本（与附录 A.4「ID 与文案分离」约束一致，ID 仅用于回传）；
4. 本规范由前端架构检查与评审把关；新增界面文案出现左列术语视为违规。

## 5. 与上游的关系

- v1.4 §5.2/§5.3 的内部字段定义**原样保留**，本规范只是新增面向人的必填字段与展示规则；
- 业务字段随清单 payload v2 一次性纳入（M1），版本兼容按 v1.4 §6.5；
- 后续新增资产类型时，先在本规范 §2 补映射行，再扩展 Schema——防止「系统词」直接漏进界面。
