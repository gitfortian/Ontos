## W3 复测：候选集注入 + 会话隔离后，#3 的协议层达标、语义层未达标（12:25）

按上一轮结论先做候选集注入，结果连带修出两个更底层的问题。

### 修复

1. **候选集注入**：新增 `AgentContextProvider`（framework-common 定义接口）+
   `ManifestCandidateContextProvider`（ontology 实现，按 `manifest_id + content_hash` 缓存），
   把指标/维度/可用模式渲染成白名单追加到提示词。单次会话 45s → 8s，模型直接输出 `metric.gmv` / `dim.region`。
2. **会话历史污染**：`AguiAgentRegistry` 只接受 `Supplier<Agent>`，拿不到 `threadId`，所有请求共用默认 session，
   `messages` 从 2 涨到 11。改为每请求独立 session。
3. **随之暴露的空响应**：独立 session 触发 EVENT_LOG 模式的「未完成工具调用对账」，
   抛 `SessionLogException: Explicit reconciliation required for unknown tool calls`，
   请求立刻返回空（20 次里 7 次）。改用 `SessionHistoryMode.LEGACY` 后归零。

### 五轮数据

| 轮次 | 改动 | 与期望一致 | 空响应 | 耗时 |
|---|---|---|---|---|
| 1 | 基线 | 56.3% | 4 | 13m36s |
| 2 | +候选集 | 50.0% | 7 | 9m07s |
| 3 | +独立 session | 56.3% | 7 | 2m54s |
| 4 | +LEGACY | **81.3%** | 0 | 4m17s |

第 5 轮拆指标：**JSON 解析 100%（20/20）、合法终态 100%（20/20）、与期望一致 62.5%（10/16）**。

### 结论

- **协议层已达标**：模型每次都输出可解析结构，且都落到五类终态之一。
- **语义层未达标且不稳定**（50%–81%）：三条失败经核查都不是框架问题——「分析客户」正确返回 `OUT_OF_MANIFEST`、

- 待办都在契约层：能力发现的输出契约缺失、澄清与超能力边界不清、需要 JSON Schema 校验 + 重试。
- **代价**：M0 不支持多轮上下文，M1 必须按 `threadId` 维护 agent 实例。

## T3.3 #4 编译器 Golden SQL：QUERY 全通过，非 QUERY 静默出错（13:10）

### 做了什么

  LOOKUP 4、LOOKUP_BATCH 3、FUNNEL 2、YOY_MOM 1。

### 结果

| 项 | 结果 |
|---|---|
| 逐字比对（SQL + 绑定值） | **20/20 一致**，失败 0 |
| 参数化 | 全部 `?` 占位，无字符串拼接 |
| dry-run | **20/20 EXPLAIN 通过**，0 语法错误 |

### 高危发现

10 条非 QUERY 用例**全部编译成功且无报错**，生成的却是聚合 SQL。
`DslValidator` 只查 `allowedModes`，编译器不读 `mode`——于是执行层会拿到一条语义错误的查询，

Golden 集由当前编译器生成后人工审阅冻结，锚定的是「当前行为」；非 QUERY 的问题被显式标为
`SILENT_WRONG_MODE` 记录，没有当成期望值冻结。M2 补齐后须重新生成并升版本。
