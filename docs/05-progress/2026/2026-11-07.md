## W3 实测：真实模型跑通，但 #3 终态重建 FAIL、#10 协议段部分通过（11:20）

用户提供 OpenAI 协议兼容端点凭据（写入 `.env.local`，已被 gitignore）。真实跑完后结论是**两项都没过**，记录如下。

### 跑通的部分

- 模型配置改为标准 OpenAI 三件套（`model` / `base-url` / `api-key`），凭据经 `ModelCreationContext` 显式传入。
- 真实连通：`call()` 6.2s 返回正常中文，`stream()` 产出 `REASONING` / `AGENT_RESULT`。
- 修的缺陷：原默认 `dashscope:qwen-plus` 的 provider 从未引入，`ModelRegistry.canResolve` 返回 false；
  前端 `AGUI_ENDPOINT` 写的是 `/agent/ontos`，服务端实际是 `/agent/run/ontos`（AG-UI 必然 404，表现为「后端没起来」）。

### #3 五类终态重建：FAIL（56.3%，9/16）

| 终态 | 命中 |
|---|---|
| 澄清四要素 | 3/4 |
| 能力发现 | 2/4 |
| 审批回传 | N/A（M0 无此能力，不计入分母也不记通过） |
| 复合子结果 | 1/4 |
| 原因码 | 3/4 |

失败模式：4 次空响应（<2s 返回且无任何文本）、3 次 180s 超时、4 次字段不满足。
根因不是模型能力，是三个配置缺口叠加：**没有候选集注入**、**agent_spawn 未收敛**（模型派生 `general-purpose-subagent` 去检索）、**token 预算与 reasoning 模型不匹配**（出现 `finish_reason=length` 且 content 为空）。
结论：需 M1 的「候选集注入 + 工具白名单」到位后重跑，不靠调 prompt 或放宽判定。
