## M3/W4 文案模板服务（2026-11-09）

> 本文件 append-only：修正请追加「更正」条目，不回改历史行。

### 交付

- **`CopyTemplateService`（`service/copy`）**：原因码 → 渲染文案的唯一入口。
  查找顺序：`reasonCode + locale` → 同原因码任意 locale → `GENERIC`；全部落空 =
  新错误码 **`1002000034 COPY_TEMPLATE_MISSING`**（v7 等没有 GENERIC 的旧清单如实报缺，不硬编码文案）。
- **渲染边界（R-26 一并落地）**：占位符按发布期 `allowedPlaceholders` 白名单替换；
  **声明了但调用方没给值 → 回退 GENERIC 并记 WARN，绝不把 `{x}` 原文透给用户**；
  文本里未声明的花括号序列按**字面量**输出（是文案的一部分，不是待填充槽）。
- **端点**：`GET /api/v1/copy-templates/{reasonCode}?locale=zh-CN&<占位符参数>`，
  独立于错误响应（M3 规格 §8 决策 3：错误契约稳定，文案版本独立升级）；
  响应带 `fallback` 标记（true = 走了 GENERIC 兜底）。
- 复用 `effectiveReasonCode()`（v7 前缀派生），老清单的 OUT_OF_MANIFEST / NO_RULE / OUT_OF_SCOPE 可直接渲染。

## 本地 IDEA 启动失败 + 日志乱码 定位与处置（10:40–11:00）

> 追加条目，不回改上文。本任务为环境 / 诊断类，不涉及阶段验收判定，M3 状态不变；
> 期间存在并行任务写入与 `git add -A` 提交，见「提交范围」一行。

### 现象与根因（两个独立问题，勿混为一谈）

1. **启动失败**：IDEA 的 `OntosApplication` 临时 Spring Boot 运行配置
   （`.idea/workspace.xml` 的 `RunManager`）只有 `SPRING_BOOT_MAIN_CLASS` 与 module，
   **未设置 Active profiles / 环境变量**。`application.yml` 的
   `ontos.datasource.*.username/password` 是无默认值占位符（M0 审计硬化 fail-closed），
   开发凭据只在 `application-local.yml`，故以空用户名连库，PG 返回 `28000`，
   `flywayInitializer` → `systemJdbcTemplate` → `publishedSnapshotRepository`
   → `manifestServiceImpl` → `manifestController` 整条装配失败，启动中止。
   与 2026-11-07 记录的「run-local-backend.sh 漏传 profile」同因：脚本已修、IDE 侧未固化。
2. **日志乱码**：与 IDEA 控制台编码无关。用 PostgreSQL v3 原生协议抓「空用户名」握手错误，
   服务端 ErrorResponse 中文字段是 **GBK 字节**（`d6c2c3fcb4edcef3` =「致命错误」），
   因 `lc_messages = Chinese (Simplified)_China.936` 且握手期 `client_encoding` 尚未协商；
   pgjdbc 按 UTF-8 解码后字符串本身已损坏，日志再怎么设编码都救不回。
   同进程业务中文日志（如 `[purgeStale][启动回收过期缓存键...]`）显示正常，
   连接建立后的普通 SQL 错误在 psql 下也是正常 UTF-8，可反证乱码只发生在握手期。

### 处置与验证（真实执行）

- 启动修复：IDEA `Active profiles = local`（或 VM options / `SPRING_PROFILES_ACTIVE` /
  Program arguments 等价写法），README 已固化指引。
