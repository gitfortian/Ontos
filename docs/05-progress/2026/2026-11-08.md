### R3 · Step 2 T3.1 路径 → Join（`506ef4b`）

- **发现 D6（静默错误结果，高）**：多个跨表维度规划出重叠路径时，同一关系被重复展开；
  两端表都已引入时 `SqlCompiler` 把该边退化成 WHERE 等值条件，可能追加本不存在的连接约束，
  属于「不拒绝但结果可能错」，比 fail-closed 拒绝更危险。
  → 已修：`JoinPathResolver` 按 `relationId` 去重复用已展开边；两端已引入但关系未展开时
  直接 `PATH_UNREACHABLE` 拒绝；保证每条 `ResolvedJoin.table` 非空，`SqlCompiler` 对缺失表

## W3 / T3.2 lookup 与 lookup_batch（2026-11-08 续 6）

- **DSL 契约**（v1.4 §6.3.1、camelCase）：`entityId` / `attributes` / `identity{propertyId,value}` /
  `identities` / `identityPropertyId`；lookup 系列以实体为入口、不要求 `metricId`。
  `limit` 默认值由固定的 100 改为 **null = 模式定档**（QUERY→max-rows、lookup→1、batch→max-batch-size），
  校验器把生效值写回 DSL，避免「客户端不传 limit 却按 100 判定」的隐式默认。
- **校验**：`DslValidator` 在 metric 必填检查前分流 lookup；校验实体已发布、投影属性属于实体且
  `lookupProjectable`、**同表**（M2 单表定档）、标识属性可定位（`filterable` 或 `existenceSensitive`）、
  单实体 `limit=1`、批量 `identities ≤ max-batch-size` 且 `limit ≥ identities.size()`；
  时间窗 / 分析参数 / 子意图 / metric 一律拒绝。
- **编译**：`SqlCompiler.compileLookup` 单表投影，别名固定 `__identity` + 属性 ID；
  单实体 `= ?` 且 **LIMIT 2** 探测「标识不唯一」，批量参数化 `IN`；物理列只来自本体属性。
- **执行与存在性保护**：`assembleLookupRows` 严格按请求顺序逐行对齐，缺失/不可见行统一
  `available=false` 且不返回任何值；`displayHints=mask` 或 `existenceSensitive` 属性强制掩码，
  **`rows` 与 `lookupRows` 同步掩码**（两个返回通道不能一明一暗）。
- 错误码 `1_002_000_015~020`（标识缺失 / 不可投影 / 跨表 / 多结果 / 批量上限 / 属性不可用）。
