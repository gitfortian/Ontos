### 交付

- **DSL**：`AnalysisParams` 新增 `cohortEvent / returnEvent / periodUnit / periods`（`subjectPropertyId` 复用），
  `DslCodec` 白名单同步；跨模式参数（funnel 的 steps/cohortWindow/stepWindow、yoy_mom 的 period）一律拒绝而非忽略。
- **校验**（`DslValidator.validateRetention` 独立分流，落实阶段中审核 D-6）：拒绝 metricId / explicitRange /
  subIntents / filters / caliberVariantId / lookup 字段；时间窗必须是服务端解析产物；cohort 与 return 事件各命中
  唯一定义、三件物理映射齐备且一致；维度只允许主体表；limit 与敏感 guardrail 沿用 funnel 口径。
- **时间**（`TimeWindowResolver.resolveRetention`）：客户端提交 `timeRange` 直接拒绝（服务端回填通道不可占用），
  `timeRange.field` 由 cohort 事件 `timeProperty` 回填，`timeExpressionRaw` 必须命中已发布模式。
- **编译**（`SqlCompiler.compileRetention`）：`cohort_first → cohort → retained` 三 CTE，
  `generate_series(0, periods-1)` 展开观察期，`count(distinct) filter (where …)` 出 cohort/retained 与留存率；
  `Clock` 注入（Asia/Shanghai）用于「最后一个完整周期」判定，单测可复现。
- **错误码**（只追加，不复用）：`RETENTION_EVENT_NOT_FOUND` 1002000035、`RETENTION_DIMENSION_UNSUPPORTED`
  1002000036、`RETENTION_PERIOD_INCOMPLETE` 1002000037。
- **服务层**：`QueryServiceImpl.isEventAnchored`（funnel / retention 同型）——跳过 metric 主资产判定、
  本体路径规划与 timeRange 的 DIMENSION 判定（事件时间属性由 EventDef 回填、非客户端输入）。
- **Golden**：[M6-Golden-v1.json](../../06-verification/evaluation/M6-Golden-v1.json)（5 正例 + 5 负例）+
  `scripts/verify/m6-golden.mjs`（`--mode=backfill|check`，按 section 组织，T1.4/T1.5 增量沿用）。
