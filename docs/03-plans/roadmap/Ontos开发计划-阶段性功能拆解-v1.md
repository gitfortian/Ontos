## 0. 起点与终点

**起点（现状）**：工程骨架已能编译、测试、启动。

| 已具备 | 仍是占位 / 未做 |
|---|---|
| 后端 Maven 多模块（framework 4 + 业务 3 + server）、yudao 风格通用层 | `PolicyService` 默认 fail-closed，仅 `local` 用 `dev-allow-all` 放行 |
| 前端**工程规范**（目录分层 / `service` 三层 / 架构检查）已按 yak-ops 迁移 | **组件层误用来源项目的 `@base-ui/react` 组件库，偏离附录 A 选型，M0 内归位**；前端四页无对话式交互主干 |
| 双数据源、Flyway 建表、Query DS RLS 演示策略、demo 清单 | `SqlCompiler` 仅单表聚合；`AnalysisMode` 只是枚举，无构造器 |
| 发布清单加载 + SHA-256 校验 + 简化本体发布校验 | 无会话状态、检索瀑布、意图提案、时间解析、文案模板、Rule 注册 |
| DSL 校验 → 参数化编译 → 只读执行（GUC 注入）→ 审计；审批 / 审计 REST | 无评测集、失败看板、Golden Query、对抗测试 |
| 后端 32 个测试 + 前端 `npm run check` / `build` 全绿 | **阶段零 PoC（尤其硬阻断项）尚未验收** |

**终点**：满足 v1.4 §19 的 8 条最终验收（语义正确性、确定性、权限安全、可审计、可运营、工程可用性、评测可信、版本可复现），
并逐条关闭 §18 上线前检查清单。**未通过 §19 不进入真实用户试运行。**

## 2. 阶段详述

### M0 · 工程基线与阶段零硬判据

**目标**：骨架能跑不算完成；把「不通过就不得进入真实数据测试」的硬判据验掉，并冻结 v1.4 §14 阶段零的全部待决事项。

**功能范围**：工程可复现基线；阶段零 PoC 执行；决策冻结；文档一致性修订。

**交付物**
- 按 v1.1 §7 阻断级别顺序执行 PoC：`#1 RLS 最终边界 → #2 发布快照可复现 → #7 跨轮差分与存在性保护 → #3 AgentScope BETA 与事件协议 → #4 编译器 Golden SQL → #8 复合意图拆分 → #10 前端 AG-UI SSE → #5 中文召回 → #9 可观测自检 → #6 pgvector（条件触发）`。
- `#1 / #2 / #7` 为**硬阻断**：越权成功 0、规范化 SQL 与参数逐字一致率 100%、跨会话规避拦截率 100%。
- `#3` 产出相对 2.0.4 的破坏性 API 差异清单；BETA 未通过不得进入生产，回退 2.0.4。
- 冻结 v1.4 §14 阶段零决策项：首发业务域、Scenario 启用时点、会话状态机、Rule 注册表、时间解析器、文案模板、语言范围、域组合策略、fail-closed 判据清单、评测门槛。
- **前端组件栈归位（R2）**：按附录 A 把临时组件库替换为 shadcn/ui + Radix；CopilotKit Headless 待 PoC #10 验收后接入。**附录 A 不改**，规范文件只保留工程约束。

**退出条件**：硬阻断 PoC 全部通过；决策项有负责人签字的结论；技术选型文档与实际基线一致；`mvn test` + `npm run check` 全绿（已满足）。

**主要风险**：把「能启动」误当作「阶段零完成」，导致后面在错误安全边界上堆功能。

### M1 · 本体与语义资产 / 发布链路

**目标**：让本体真正参与概念解析、关系路径、属性投影与授权，而不是一张实体目录。

**功能范围**：本体元模型（Class / Property / Relation / Constraint / Mapping）；语义资产（Metric 口径变体、Dimension、Event、Model）；版本化发布流水线；不可变清单；资产 Owner 与审核流。

**交付物**
- 元模型与首发本体样例（v1.4 §5.6），含 `lookup_projectable`、`existence_sensitive`、`display_hints`、口语/拼音别名、PII 标记。
- Git → CI → 发布的资产流水线：发布前强制 `OntologyPublishValidator` 及基数 / 粒度 / 引用完整性校验；产出 `manifest_id + content_hash` 与全版本组合。
- 有限关系路径规划器（类型合法、跳数受限），禁止隐式业务规则推导。
- 清单加载、跨副本一致性与失效 / 回滚；清单管理界面（版本 diff、指标 / 概念 / 关系浏览）。
- 资产变更影响分析：哪些清单、VQR、Scenario、Rule 受影响。

**涉及模块**：`ontos-module-ontology` 扩展；建议新增 `ontos-module-catalog` 承载语义资产与发布流水线；前端 `ontology` 域扩展。

**退出条件**：任一查询可追溯到「本体路径 → Model/Join Path → Metric/Dimension → SQL」；未授权概念 / 关系 / 字段被拒；同一 DSL + 同一清单重复编译逐字一致（PoC #2 纳入回归）。

**主要风险**：本体退化成目录，路径规划缺席，后续所有确定性都建在空中。

---

### M2 · 确定性编译与执行内核

**目标**：把当前「单表聚合骨架」升级为完整的受约束编译链路。

**功能范围**：DSL Schema 完整化（额外字段拒绝、类型 / 基数 / 关系路径 / 资产 ID 校验）；路径 → Join 展开；参数化 SQL 编译；dry-plan / dry-run；成本与资源控制；结果约束。

**交付物**
- 完整 DSL 校验器：Scenario scope、能力、`metric.allowed_modes`、口径、跨域组合、累计敏感约束；拒绝自由 SQL、绝对日期、候选集外 ID。
- 编译器：依据已发布映射展开 Model / Join / 指标 / 规则 / 展示转换 / 权限谓词 / 成本上限；参数零字符串拼接。
- `dry-plan`（不执行）与 `dry-run`（受限执行）共用同一编译产物；查询超时、扫描量、行数、子查询总量控制。
- ≥30 条 Golden SQL 逐字比对（PoC #4），覆盖 `query / lookup / lookup_batch / funnel / yoy_mom`。
- Query DS 执行边界：只读账号 + `FORCE RLS` + 事务级 GUC，连接复用不串号（PoC #1）。

**涉及模块**：`ontos-module-query` 的 `core/dsl`、`core/compiler`、`core/executor`；前端 `ask` 域的编译调试页。

**退出条件**：Golden SQL 100% 一致；LLM 无法通过任何工具提交自由 SQL 或绝对日期；未授权路径 / 字段 / 行访问全部拒绝；dry-run 可回放。

**主要风险**：为图快在编译器里做字符串拼接或隐式降级，破坏确定性。

---

### M3 · 简单问法最小闭环

**目标**：简单问题走最短路径，不被迫套聚合范式。

**功能范围**：`lookup` 单实体 / 批量、属性投影、布尔判定、口径变体、相对时间解析、原因码文案模板、存在性保护。

**交付物**
- `lookup` Analysis Mode 与 `skill.entity_lookup`；批量逐行差异保护、存在性保护（`ATTRIBUTE_NOT_AVAILABLE` 不泄露存在性）。
- `boolean_rule` Metric 与 Rule 注册中心最小闭环（≥1 条 Rule，禁止内联表达式 / 自由阈值）。
- 口径变体最小闭环（≥1 个变体，含 `CALIBER_AMBIGUOUS` 澄清）。
- 时间解析器（≥3 个模式：上个月 / 上季度 / 近 7 天），记录 `time_expression_raw`，版本化。
- 文案模板服务：原因码 → 模板，禁止占位符校验，ID 与文案分离。

**涉及模块**：建议新增 `ontos-module-agent`（能力注册）或先在 `ontos-module-query` 内按功能包隔离；`ontos-module-system` 承载审批；前端 `ask` 域增加澄清 / 结果展示。

**退出条件**：lookup 单实体 / 批量 / 布尔判定闭环通过；口径变体与时间解析闭环通过；存在性泄露与批量差异泄露为 0；PII 裁剪生效。

**主要风险**：把简单问法又塞回复杂聚合链路，导致口径与性能双输。

---

### M4 · 身份、权限与安全治理

**目标**：把「应用层策略 + DB 层 RLS」做成双边界，替换当前 fail-closed 占位实现。

**功能范围**：认证网关注入身份；策略快照（用户 / 租户 / 角色 / 数据域 / 域组合）；字段 / 行权限；审批；审计完整链路；脱敏；跨轮累计敏感检测。

**交付物**
- `PolicyService` 接入 System DB 策略快照，删除 `dev-allow-all` 生产路径；缓存绑定租户与策略版本。
- 域组合策略、敏感字段裁剪、`label` 型判定结果策略、存在性保护、跨轮累计与跨会话规避检测（PoC #7）。
- 审批流：HITL 回传、超时失效、决策人取自上下文；审计补齐 §18「可审计」全部字段（含 `parent_request_id` / `sub_intent_id` / `context_delta` / 版本链路）。
- 提示注入检查点：候选集外 ID、身份声明、能力边界拒答；前端事件日志脱敏（附录 A A.4）。

**涉及模块**：`ontos-module-system`（policy / approval / audit / guard）；`ontos-framework/*starter-web*`（身份上下文）；前端 `approvals` / `audit` 域。

**退出条件**：越权、注入、聚合泄露、跨轮差分、跨域组合测试全部通过且严重违规为 0；审计可完整回放；PoC #1 / #7 纳入自动化回归。

**主要风险**：把安全做成「只在应用层的 if 判断」，DB 层边界缺失。

---

### M5 · 会话、意图编排与 AG-UI 链路

**目标**：把自然语言接进确定性链路，且上下文权威始终在服务端。

**功能范围**：会话状态机；概念解析与指代消解；检索瀑布；Intent Proposal；结构化终态（澄清 / discovery / 拒答 / 引导 / 复用）；AG-UI 事件流。

**交付物**
- 会话状态机：`resolved_entities`、`session_query_context`、`session_scenario_state`、`turn_index`、增量合并、纠正回退、跨会话不沿用。
- 检索瀑布：精确 → 词典 → 受限模糊（仅作澄清候选，模糊候选进入 DSL 次数为 0）；授权子图内召回。
- LLM 编排器只输出候选与参数；Proposal 来源完整性校验、身份不可覆盖。
- AG-UI 六类事件端到端：`RUN_*` / `TEXT_MESSAGE_*` / `TOOL_CALL_*` / `CUSTOM` / HITL interrupt / state；断线重连幂等；shared state 服务端只读投影。
- 澄清四要素、能力边界拒答、discovery 引导式发现的最小交互闭环。

**涉及模块**：建议新增 `ontos-module-session`、`ontos-module-agent`；`ontos-framework/*starter-agent*`；前端 `ask` 域对话主干。

**退出条件**：20 次会话中 5 类结构化终态重建成功率 100%（PoC #3）；多轮指代与增量合并达标、跨会话不串号；`RUN_STARTED.input` 前端脱敏验证通过（PoC #10）。

**主要风险**：客户端自由修改上下文，或自研 SSE 事件模型偏离 AG-UI 协议。

---

### M6 · 分析模式、Scenario / Skill 与复合意图

**目标**：在确定性内核之上扩展能力，每个能力独立验收，不合并 SQL。

**功能范围**：8 种 Analysis Mode 构造器（按序）；Scenario 资产化；Skill 注册中心；复合意图拆分；VQR 运营闭环。

**交付物**
- 按 v1.4 阶段三 (a) 顺序：同环比 → 漏斗 → 留存 → 简单归因 → 其余模式；每个独立完成口径契约、DSL Schema、确定性构造器、Golden Query、边界与性能验收。
- Scenario 资产模型与入口路由（inherit / manual / auto / cold_start / none）、scope 裁剪、`frozen_calibers`、冷启动地图、发布 / 版本 / 失效 / 回滚。
- Skill 注册 / 审核 / 参数 Schema / `required_capabilities` / `allowed_scenario_ids` / `approximation_of` / 实现版本。
- 复合意图：子查询序列、独立编译与独立授权、结果隔离、部分失败可解释、审计父子关系完整（PoC #8）。
- VQR 生命周期与人工审核：绑定全版本组合、当前权限重编译、缓存隔离、失效与回滚（v1.4 §11）。

**涉及模块**：`ontos-module-query`（模式构造器）、建议新增 `ontos-module-catalog`（Scenario / Skill / VQR 资产）；前端新增资产运营页面。

**退出条件**：每个已发布模式 / Skill 达到门槛；自定义 Scenario 不改编译器即可上线且 scope 越界被拒；复合查询合并 SQL 次数 0、共享中间结果 0；VQR 不绕过权限与成本校验。

**主要风险**：模式膨胀导致编译器分叉、确定性退化；Scenario 越权扩大 scope。

### M7 · 评测、对抗防线与可观测

**目标**：用自有评测证明效果，而不是靠演示。

**功能范围**：零号冒烟、正式评测集、对照 / 消融、分层统计与门槛、失败看板、追踪与压测。

**交付物**
- 冻结正式评测集与 gold（含版本哈希），指标按 `scenario_entry_mode` / `query_shape` / `turn_type` / `risk_type` 分层统计并给置信区间。
- 对抗防线专项：注入、跨轮差分、跨域组合、能力边界、discovery；安全违规为 0 的硬门槛。
- 失败看板 5 维下钻、失败样本分类、纠正样本进回归集。
- 复用框架观测能力（不自研埋点重复），trace 关联问题 → DSL → SQL → 结果；P95 延迟 / 成本 / 并发 SLO 压测。
- 零号冒烟实验与正式评估通过条件（v1.4 §13）。

**涉及模块**：建议新增 `ontos-module-eval`（评测与看板）；`ontos-module-system`（审计与监控指标）；前端 `audit` 域扩展失败看板。

**退出条件**：§13.5 评测通过条件满足；§19「评测可信」「工程可用性」达标；失败样本可分类到根因。

**主要风险**：评测集边做边改，效果口径漂移，最后无法证明收益。

### M8 · 上线与规模化

**目标**：把通过验收的系统变成可运维的产品。

**功能范围**：网关与部署、灰度与回滚、SLO 与灾备、容量、条件触发的扩展能力。

**交付物**
- 认证网关、限流、静态资源由 Spring Boot 单体托管（不引入独立前端服务）；多副本清单一致性与发布可见延迟（PoC #9）。
- 灰度 / 回滚 / 灾备 / 备份、容量与多租户资源队列、SLO 监控告警。
- 上线前逐条关闭 §18 检查清单，出具 §19 八条验收报告。
- **条件触发（不排进主干）**：高级召回（图谱多跳 / 向量 + BM25 / rerank，仅当配对评测证明收益）、外部资产交换、多语言文案扩展。

**退出条件**：§18 全项打勾且 §19 八条全部满足；严重安全违规 0；回滚演练成功。

**主要风险**：在核心链路未稳时提前做高级召回，把复杂度引入未验证的主干。

## 4. 闸门与并行原则

1. **硬闸门不过不进真实数据**：M0 的 PoC `#1 / #2 / #7` 是全局前置，不是某个阶段的可选项。
2. **每个阶段只有一条退出条件**：可测、可复现、有证据；未达门槛不进入下一阶段，避免堆叠返工。
3. **安全与评测不许后置**：M4 与 M1–M3 并行，M7 从 M1 起同步建设。
4. **能力按注册制扩展**：Analysis Mode 封闭枚举、Skill / Rule / Scenario 走审核与版本，禁止内联脚本与自由 SQL。
5. **高级召回条件触发**：M8 才评估，且必须有配对评测收益证据。
