## 0. 背景与借鉴定档

负责人指定参考 `D:/tianxy/code/data-ops/data-ops-plugins/data-ops-plugin-datasource`（SPI + ServiceLoader +
DriverShim 外置驱动）。逐项裁决：

| 借鉴 | 不借鉴 | 原因 |
|---|---|---|
| 稳定 SPI 模块 + `META-INF/services` 注册 | — | 插件发现的标准姿势 |
| ServiceLoader + 启动期 fail-fast 注册表（重复 type / apiVersion / 能力校验） | — | 带病启动比失败更危险 |
| immutable descriptor 携带能力与配置字段 | `DataSourceDbType` 封闭枚举 | 封闭枚举迫使第三方改核心；改用 `String type` + 注册表查重 |
| Gateway 统一映射 SPI 异常 → 业务错误码 | `DataSourceConnection.password()` 裸 getter | 换 `Secret` 包装，toString 固定打码 |
| 外置驱动 jar（URLClassLoader + DriverShim） | `createSqlExecutor` / `buildSqlTemplate` / `resolveSql` | **插件不得生成或执行 SQL**——会绕过 DSL 校验、RLS 与审计；驱动外置留待 Phase 3 |
| — | 插件类热加载 | ServiceLoader 仅启动期；热卸载存在 classloader 泄漏 |

## 1. Phase 1 范围 / 非目标

**范围**：SPI 契约 + 内置 PostgreSQL 插件 + 注册表 + 目录/测试/摘要接口 + 数据源页接入真实库目录。

**非目标（fail-closed 边界）**：

1. 插件不生成、不执行 SQL；查询执行仍是 `QueryExecutor` 只读通道（RLS GUC + 只读角色不变）。
2. 插件不接触租户上下文；连接仅用于元数据与连通性验证。
3. 不保存连接配置、不做多源注册；`Property.column → datasetId + column` 属 Phase 2。
4. 不做插件热加载；外置驱动 jar 属 Phase 3。

## 2. SPI 契约（`ontos-spi-datasource`，纯 Java）

```java
public interface DataSourcePlugin {
    String type();                                  // "postgresql"，非封闭枚举
    DataSourceDescriptor descriptor();              // apiVersion / capabilities / configFields（不可变）
    DataSourceConnection parse(Map<String, String> config);
    void testConnection(DataSourceConnection connection, Duration timeout);
    DataSourceCatalog catalog(DataSourceConnection connection);
}

public interface DataSourceCatalog extends AutoCloseable {
    List<String> schemas();
    List<TableMeta> tables(String schema);
    List<ColumnMeta> columns(TableRef table);
    void close();
}
```

- `DataSourceCapability`：Phase 1 仅 `CONNECTION_TEST` / `CATALOG_METADATA`；调用前必须先查能力。
- `DataSourceConnection.password` 为 `Secret` 包装：record 默认 toString 调用组件 toString，
  输出 `***`；取真值只能显式 `value()`。
- `DataSourcePluginException` 按 `Operation`（PARAMETER / CONNECTIVITY / CATALOG）分类，
  平台据此映射错误码；消息不得含 secret。
- 禁止向 SPI 增加 `Map<String,Object>` 式协议；新语义一律加 typed record。

## 3. 模块与依赖方向

```text
ontos-spi-datasource      纯 Java，零依赖
ontos-plugin-jdbc         PostgreSQL 实现 + META-INF/services；驱动仅 runtime 作用域
ontos-module-datasource   注册表 + 目录服务 + 管理端点（→ spi / ontology / framework）
```

ArchUnit 新增两条：`datasource_must_not_depend_on_runtime_modules`、
`only_server_may_depend_on_datasource`——与 catalog 同构，插件不得借道执行链。

## 4. 注册表与错误码

- `DataSourcePluginRegistry`：`@PostConstruct` 经 `ServiceLoader` 发现；`collect` 校验
  type 非空、descriptor 一致、apiVersion = `1`、能力非空、type 全局唯一，违规启动失败。
- 错误码启用 `1_006` 段（`1_006_000_101`–`106`）。注：AGENTS.md §3 分段描述（仅 1_001–1_003）
  为既有欠账，与 catalog 的 1_005 一同待修订。

## 5. 接口（管理面，PublishGuard 闸门）

| 端点 | 说明 |
|---|---|
| `GET /api/v1/catalog/data-sources` | 摘要：连接信息（URL 脱敏）+ 清单引用表 + 已注册插件 |
| `GET .../current/catalog?schema=` | 真实库目录：schema 列表 + 指定 schema 的表 |
| `GET .../current/columns?schema=&table=` | 指定表列元数据 |
| `POST .../{type}/test` | 连通性测试（不保存配置；超时 10s，驱动属性 connectTimeout） |

`Property.column` 反推的「清单引用表」保留为对照视图；真实目录为准。

### 8.2 边界（未做，触发点登记）

- **datasetId 化执行**：注册源当前只用于目录浏览与建模取列；业务查询仍走 yml 当前查询库。按源执行需要 `Property.column → datasetId + column` 并触发 Model 层（Phase 2 后半）。

- 多方言插件（MySQL/Doris 等）：插件按需追加，SPI 已就绪。
