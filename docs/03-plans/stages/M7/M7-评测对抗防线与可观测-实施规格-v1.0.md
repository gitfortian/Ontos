## 1. 目标与非目标

**目标**（roadmap M7）：用自有评测证明效果，而不是靠演示。

1. **评测可信**：正式评测集与 gold 冻结且带版本哈希；指标按 `scenario_entry_mode / query_shape / turn_type / risk_type` 分层统计并给置信区间；**评测结果可由版本与数据哈希复现**。
2. **LLM 路径评测**（E-7）：同一 test 集在 LLM 编排路径下运行并与确定性降级路径**配对比较**；`fallback_reason` 单列；意图一致率按 R-1 代理口径报告并声明局限。
3. **对抗防线专项**：注入、跨轮差分、跨域组合、能力边界、discovery 五类，加 LLM 路径新攻击面；安全违规为 0 的硬门槛。
4. **失败看板闭环**：5 维下钻 + 失败样本根因分类（对齐 §12.3 原因码族）+ **纠正样本自动回流**（状态事件、回流 API、回归集写入、集合隔离）。
5. **可观测与 SLO**：复用 OTel/Studio + Actuator（不自研埋点），trace 关联问题 → DSL → SQL → 结果并覆盖 LLM 调用与成本；P95 / 成本 / 并发 SLO 压测。
6. **补齐 M6 报告的代码类附条件项（四项）**：纠正样本自动回流（M6 报告 v2 §1 第 4 项「部分满足」）、VQR `paramsSchema` 运行时 type/min/max 约束、复合非 `ServiceException` 子级隔离、Skill capabilities 发布期闸门（D-22）；E-5/E-6/E-7 分别由 E1/E2/E3 覆盖，不在此重复。

**非目标（边界外）**：

- **高级召回**（图谱多跳 / 向量 + BM25 / rerank）：条件触发归 M8，需配对评测收益证据（技术选型 §15）。
- **多域组合判定实现**（R-31）：首发单域口径不变，M7 只做边界声明与探针占位；判定实现随多域 ADR。
- **CopilotKit Headless 切换**：ADR-0010 决策维持，观察项非阻塞。
- **真实用户试运行 / 生产发布**：属 M8；M7 只对评测与观测负责。
- **评测集边做边改**：test 集冻结后只允许「升版 + 归档 + 登记哈希」，不允许就地改题（ADR-0005）。
- **温度/超时参数承诺**：框架未暴露（R-3），M7 不承诺温度可控，也不自研 HTTP 调用绕开 AgentScope。

## 3. 设计

### 3.1 评测运行模型与统计口径

每次评测运行必须锚定并记录：`testSetVersion + contentHash`、生效清单 `manifest_id + contentHash`、策略快照版本、编译器版本、时间解析器 / 文案模板 / Scenario / Skill / VQR 版本、**模型名 + 实际参数 + prompt 版本**、执行路径（`llm` / `deterministic_fallback`）。运行产物落 `docs/06-verification/evaluation/`，文件名带版本或日期，**不得覆盖历史证据**（T55-3 教训）。

统计口径沿用 [评测统计口径 v1](../../../06-verification/evaluation/评测统计口径-v1.md)：
- 主指标分母不含 skip；`error` 整批重跑；有效样本为 0 的分层不报成功率；
- 默认 Wilson 95%；`n < 30` 标「小样本」；Clopper–Pearson 仅争议复核；
- **LLM vs 降级路径同一 test 集配对**：二元结果用 McNemar，连续指标（成本/延迟）用配对 bootstrap（B=10000，报 2.5/97.5 分位）；
- 阈值唯一出处 [ADR-0005](../../../01-decisions/ADR-0005-评测门槛与PoC执行责任.md)（§7 建议初值），**先冻结、后看结果，不得下调**。

### 3.2 LLM 路径评测（E-7）

- **运行前提**：稳定模型服务可用（base-url / api-key / 模型名三件套）；模型名在 W2 启动前由负责人指定并写入运行证据；**温度不可控**（R-3），以「固定模型 + 多次运行 + 原始响应留痕」替代温度承诺。
- **runner**：新增 `scripts/verify/llm-test-runner.mjs`（R-10）——DSL 题把 `question` 发 `/api/v1/ask/runs`，多轮题逐轮发送，场景 flow 题复用确认回传；**不得调用 `buildDsl` 绕过 NL**；`test-runner.mjs` 判据不改（保持降级路径基线）。
- **路径判定**：请求实际走 `ontos.agent.enabled=true`；因模型不可用/超时/解析失败落到降级路径的，标记 `fallback_reason`，**不计入 LLM 路径成功率**。
- **意图一致率（代理口径，R-1）**：逐题记录 Proposal → 最终 DSL，统计 `necessary` 命中率、`forbidden` 违反率、终态一致率、澄清正确率；报告显式声明「非 Proposal 稳定性结论」，`acceptableProposals` 补测登记为 M8 前项。
- **对比口径**：同一 test 集分别跑 LLM 与降级路径，并列报告；差异归因到「意图/澄清/多轮合并」与「编译执行」两段，不合并结论。
- **失败分类**：模型不可用、超时、Proposal 合法性拒绝、DSL 校验拒绝、执行拒绝、文案/终态不符；每类给样本与复现命令。

### 3.3 E-5 品类粒度实现口径（决策 1）

按 [ADR-0016](../../../01-decisions/ADR-0016-品类维度与订单事实指标的粒度边界.md) 采用**方案 A：新增订单项级指标**：

- 新增 `order_item` 粒度指标（销量 / 订单项金额），指标契约明确「订单项口径」，与订单级指标分列；
- `dim.product_category` 只允许与订单项级指标组合；订单级指标（GMV / 订单数 / 客单价 / 客户数）不得与品类维度组合，运行时仍 fail-closed `1002000014`；
- 落点：清单指标定义 + `allowed_dimensions` / 粒度校验 + DSL 契约 + test 集升版 + Scenario/Skill 能力宣示；**新发 ADR-0018 记录实现口径**（ADR-0016 要求「M7 若决定实现，需新发 ADR 并同步清单/test 集」）。
- **实施期表述纠正（2026-11-11，通过标准未放宽）**：`t-agg-single-17` / `t-yoy-06` 题面是「各品类**订单数**」，方案 A 不能使其可编译（订单级指标 × 品类仍扩散）——2 题去掉 `skipReason`、**转为预期拒绝正例进分母**（判据 = rejected + `1002000014`，runner 已支持），另补 2 题「各品类**销量**」正例（QUERY / YOY_MOM）；订单项金额（quantity×price）因 `order_item` 无金额列且指标模型不支持表达式，登记为后续（需加列或表达式能力），不在本阶段阻塞。

### 3.4 E-6 auto 入口场景资产（决策 2）

- 新增 `scenario.sales.auto`（`entry_mode=auto_if_confident`，单域、`entry_hints` 精确/子串唯一命中、scope 收窄、`frozen_calibers` 继承 `scenario.sales`），不改变 `scenario.sales` 的 manual 行为；
- 沿用 M6 决策 4 的确定性置信口径（不引入 LLM 置信度数值）：唯一命中自动进入；多命中/无命中回退自由问数；
- 补 ≥3 道 `scenario_entry_mode=auto` test 题（现有 0 题），覆盖唯一命中/多命中/无命中；资产发布走 dry-run → 确认 → 激活，清单升版登记哈希。

### 3.5 对抗防线专项

在 M6 已有探针基础上扩展，保持「全拒 + 零泄露」：

| 攻击面 | 新增重点 |

| 提示注入 | 中文/英文/混合注入族、系统提示泄露、工具参数注入；LLM 路径与降级路径分别验 |
| 跨轮差分 | 逐步收窄、差分对、跨会话规避（session 级清零后 user 级仍拦截） |
| 跨域组合 | 首发单域边界声明 + 探针占位（R-31，多域 ADR 前不做判定实现） |
| 能力边界 | 候选集外资产、未发布 Skill/VQR、越权 Scenario、伪造确认回传 |
| discovery | 诱导执行、候选集外 ID、拒绝路径不得泄露存在性 |
| LLM 路径新面 | 工具调用越权（不得暴露 `execute_query`）、上下文污染、输出解析降级、模型不可用时的 fail-closed |

判据：严重越权与敏感数据泄露 **0**；存在性泄露 **0**；跨轮差分泄露 **0**；跨域组合违规 **0**（单域边界内）；注入成功 **0**；应拒答而执行 **0**。

### 3.6 失败看板闭环与纠正样本回流

- **不改 V17**（只追加语义，R-9）；新增 **V18 `evaluation_failure_sample_status_event`**：`id / tenant_id / sample_id / from_status / to_status / actor / note / created_at`，只追加；当前态由最新事件派生。
- **状态机**：`open → triaged → fixed → regressed / ignored`；非法迁移拒绝；租户隔离不变。
- **根因分类（R-12）**：`root_cause_category` 对齐 §12.3 原因码族（术语/别名、实体歧义、口径冲突/未定义/变体、Scenario 入口/无权/scope/frozen、Analysis Mode、Skill、指标模式不匹配、属性不可用、Rule、跨域、累计敏感、注入、能力边界、意图未发现、时间未解析、近似降级、用户纠正、复合子失败、多轮、参数缺失、DSL 非法、权限、粒度、编译、执行、结果质量），共 ≥20 类。
- **回流 API**：审核后将失败样本写入 **dev/validation 回归集**（生成样本 ID 与来源链接）；**禁止直接写 test 集**；写入需 `fixed` 状态 + 修复提交号。
- **闭环证据**：登记 → 分类 → 修复 → 回流 → 回归运行通过（或豁免记录）全链 E2E。

### 3.7 可观测与 SLO

- 复用 AgentScope OTel / Studio + Spring Boot Actuator，**不自研埋点**；新增 **V19 `llm_call_trace`**（R-13）：`request_id / tenant_id / model / duration_ms / prompt_tokens / completion_tokens / fallback_reason / created_at`；**统计写入失败只记日志、不阻断业务**（区别于 `audit_log` 的「写失败即整单失败」合规约束）。
- 指标：P50/P95/P99、rps、错误率、超时率、token 成本、缓存命中率、失败样本数；按 `scenario_entry_mode` / `query_shape` / `risk_type` 可切分。
- 压测：三档并发（1/8/16）+ LLM 路径抽样（成本受限）；SLO 阈值看正式结果前冻结（决策 8），不得事后下调。
