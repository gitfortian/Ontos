## 1. 范围与不做的事

**做**：把「骨架能跑」变成「可信基线」——硬阻断 PoC 验收、BETA 与前端协议准入、阶段零决策冻结、前端组件栈归位、评测集与门槛冻结、文档与进度基建收口。

**明确不做**（属于后续阶段，M0 不得借 PoC 之名提前实现）：

| 不做 | 归属 |
|---|---|
| 本体元模型、语义资产编辑与 CI 发布流水线 | M1 |
| 完整 DSL 校验、路径规划、8 种 Analysis Mode 构造器 | M2 / M6 |
| 策略快照产品化、会话状态机、检索瀑布、意图编排 | M4 / M5 |
| 失败看板、追踪压测、高级召回、多租户容量 | M7 / M8 |
| 真实业务数据的功能测试 | 硬阻断通过前一律禁止 |

**M0 的核心判断**：v1.1 §7 列了 10 个 PoC，其中 `#4 / #8 / #5 / #9 / #6` 依赖 M2–M8 才具备的产品能力。
M0 对这五项**只交付判据定义、Golden 样本与最小探针**（验证规则可行、集可跑），不要求跑出通过结论；
完整验收随对应阶段完成并在报告里回填。否则 M0 会被无限撑大，或在骨架上伪造通过结果。

## 3. 设计

### 3.1 产物落点（不新增产品表 / 产品端点）

| 产物 | 落点 | 模板 |
|---|---|---|
| PoC 报告（命名 `PoC-NN-<主题>.md`） | `../../../06-verification/poc/` | [验证报告模板](../../../00-governance/templates/验证报告-模板.md) |
| 评测集 / Golden 样本 | `../../../06-verification/evaluation/` | 验证报告模板 |
| 决策记录 | `../../../01-decisions/` | [ADR 模板](../../../00-governance/templates/ADR-模板.md) |
| 版本事实台账 | `../../../07-references/` | 规格模板 |
| 进度快照 | `../../../05-progress/2026/` | [进度快照模板](../../../00-governance/templates/进度快照-模板.md) |

PoC 探针一律放在 `src/test` 或独立验证工程，**不进入 `src/main`、不新增生产端点、不改现有 `/api/v1` 契约**。
确需临时端点的只允许在 `test` profile 下注册，并在报告里注明清理方式。

### 3.2 接口契约

- 现有 `/api/v1/query/{compile,execute}`、`/api/v1/ontology/manifests/current`、`/api/v1/approvals`、`/api/v1/audit-logs`、`/agent/ontos` 契约保持不变。
- `#2` 复用 `compile` 端点做 100 次重复编译比对；`#1` 直连 Query DS 做连接级验证，绕过应用层。
- `#3 / #10` 通过独立探针订阅 AG-UI 事件，不改动产品侧 `OntosAgentFactory` 的注册方式。

### 3.3 关键流程

**PoC 流水线**：环境自检 → `#1` → `#2` → `#7`（三项硬阻断逐项出具报告，失败即停）→ `#3` BETA 准入 → `#10` 前端协议准入 → 其余五项交付判据与探针 → 汇总到 M0 验收报告。

**前端组件栈归位流程**：确认 R2 范围 → 替换共享组件层 → 迁移页面引用 → 回归工程规范检查 → 更新规范文件中的「临时状态」标注 → 待 `#10` 结论决定是否接入 CopilotKit Headless。**附录 A 不修改。**

**决策冻结流程**：逐项形成 ADR（依据 / 备选 / 影响 / 回退）→ 负责人签字 → 更新本规格 §6 的证据列 → 写入进度快照。

## 7. 风险与回退

| 风险 | 触发 | 回退 / 应对 |
|---|---|---|
| PG 18 环境不可用（当前无 docker 命令） | T2.1 无法启动 | 先解决运行环境或改用 CI 上的 PG18 实例；**不得用非目标数据库出报告** |

| PoC 依赖后续阶段能力 | 想提前实现 M2–M8 功能 | 坚持「只定义判据 + 探针」，能力归对应阶段；在 PoC 总览显式标注 |

| 规格未评审即开工 | 依赖循环、口径不清的任务被直接执行 | 先完成技术评审并定稿（§8），再放行编码 |
