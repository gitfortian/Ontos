## 本地 IDEA 启动失败 + 日志乱码（同日 10:40–11:00）

- 启动失败根因：`.idea/workspace.xml` 的 `OntosApplication` 临时 Spring Boot 配置没有 Active profiles / 环境变量；`application.yml` 的 DB 凭据是空占位符（fail-closed），空用户名连库 → PG `28000` → `flywayInitializer` 失败 → `systemJdbcTemplate` / `ManifestServiceImpl` 整条装配链崩。与 11-07「脚本漏传 profile」同因。修法：Active profiles 填 `local`（或 VM options / `SPRING_PROFILES_ACTIVE` / Program arguments）；**不要**把默认凭据写回 `application.yml`。
- 乱码根因（用 PG v3 原生协议抓包实测）：PG18 `lc_messages = Chinese (Simplified)_China.936`，握手期（`client_encoding` 未协商）服务端 ErrorResponse 中文是 **GBK 字节**（`d6c2c3fcb4edcef3`=「致命错误」），pgjdbc 按 UTF-8 解码 → 字符串本身损坏，改 IDEA 控制台编码无效；业务中文日志与建连后的 SQL 错误均正常，反证乱码只在握手期。
- 处置：本机 PG18 执行 `ALTER SYSTEM SET lc_messages='C'` + `SELECT pg_reload_conf()`（两条必须分开 `-c` 传，`ALTER SYSTEM` 不能在事务块内执行）；新连接 `show lc_messages`=C；复现启动错误变纯英文 `FATAL: no PostgreSQL user name specified in startup packet`，零乱码。回退 `ALTER SYSTEM RESET lc_messages` + reload。只改消息语言，不动数据 / 角色 / 权限。
- 验证：无 profile `EXIT=1` 精确复现 `28000`；local profile `Started OntosApplication in 9.524s`、Flyway 6 迁移 validate、双 Hikari 池建连、health UP；`-Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8` 下业务中文正常。check-docs 69 文档 / 561 链接、git diff --check OK。
- 改动：仅根 `README.md`（IDEA profile 指引、compose 连接串差异、日志编码根因与回退）+ 今日进度快照；未改 `src/main/**`。期间并行任务 `git add -A` 把 README 前两处编辑顺带提交进 `6f0930c`，本次剩余改动仍在工作区未提交。
