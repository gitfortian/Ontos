## W2 硬阻断 PoC 收口（T2.2–T2.5）

- **T2.2 `#2` 系统级 PASS**：`scripts/poc/run-poc02.mjs` 自己拉起 jar → 100 次编译 → 杀进程 → 再拉，共 3 个 JVM。
  比对口径必须**排除** `X-Request-Id`（每请求随机）与 `CompiledQuery.compiledAt`（编译时刻），否则永不一致；
  `QueryCompileRespVO` 本身不暴露 compiledAt，所以按响应体比对即可。实测 300/300 逐字一致。
- **T2.3 `#7` 探针级，现行初值 FAIL**：`scripts/poc/Poc07CrossRoundDifferential.java`（零依赖单文件）。
  核心发现——`T(L1)=8` 拦不住**首次精确差分**：`SUM(20 行) − SUM(19 行)` = 那 1 个 VIP 的 salary，两轮即泄露；
  累计阈值对 `w(3) < T(8)` 的单次命中天然无效。把 T 降到 4 能堵住，但正常用户第 4 次同类查询就被转审批（误报 25%），
  与 ≤2% 判据互斥。可行解是把「基数差 1 且结果集包含」的精确差分从累计权重改为**即时转审批**（实测 0 泄露 / 0 误报）。
- **三条规则解释约束**（按字面最宽解释必然撞破误报率判据，需写入 §4.8.2）：
  差分对要求结果集**包含关系**（否则 `region=华东` vs `region=华南` 也算差分，结果却不相交）；
  连续收窄要求基数**严格下降**（「非增」会把基数不变的条件切换算成收窄）；
  L1 个体值（基数 ≤1）直接转审批，不随累计计数放行。
- **闸门结论：G1 未关闭，不放行**。真实敏感数据测试禁止、M1 编码不启动；W2 收尾/W3/W4/W6 允许继续。
