## v21 渠道维度语义升级（2026-11-12）

负责人指出「按渠道分析应涉及订单与渠道两个业务对象」。核查：`dim.channel` 挂 `orders.channel`（订单冗余列），只碰订单一个对象；关系 `ontology.Order.attributedToChannel`（`orders.channel_id → channel.id`，N:1，queryable/goldenPath）存在但没被用。**数据上 `orders.channel` 与 `channel.name` 取值相同**（线上/线下），所以结果没错、建模退化。

**方案 A（新增不改）**：`dim.channel_name` = `concept.channel` + `property.channel.name`；`dim.channel` 保留，summary 改为「订单表记录的渠道名称快照」；7 个订单级指标授权新维度；订单项指标**不加**（两跳，粒度边界另评）。

**真服务 SQL 对比**（这是"两个对象"的硬证据）：
- `dim.channel` → `from "orders" group by "orders"."channel"`，joins=[]
- `dim.channel_name` → `from "orders" join "channel" on "orders"."channel_id"="channel"."id" group by "channel"."name"`，joins 含 relationId/direction/cardinality

**发布路径四步（重要）**：加维度授权会改 `metric.gmv` 定义 → VQR 保守判定失效。必须：
`发布 v21（vqrs:0）→ 激活 → 再发同内容（vqrs:1）→ 激活`。
跳过激活直接再发仍失效（oldPayload 还是 v20）。**同一资产文件两次发布 contentHash 不同**（VQR 清理改变了 payload）。
